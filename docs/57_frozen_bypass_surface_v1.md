# 冻结的绕过面说明（v1）

**状态:** 稳定期契约，面向独立测试方与审计方。本文件不是安全承诺，也不改变任何
运行行为。中文叙述，判定词表与字段名保留英文原文。

**适用版本:** 0.9.3 及之后，直到本文件被显式修订。

## 1. 防护目标与非目标

本项目的防护目标是**仿真可信度**，不是**安全性**：

- 目标：防止 **agent 非恶意改动** 导致两类后果——
  1. 实际执行的不是被审计的实现，但清单声称是；
  2. 结论的证据等级高于实际支撑程度。
- 非目标：抵御恶意攻击、沙箱隔离、进程/用户身份认证、签名与密钥管理。

唯一的判定标准：**每个防护必须能一句话说清"它守的是哪一类非恶意失败"**。
说不出来的，不予实现。

## 2. 仍然接受提报、并且会修的缺陷

| 类别 | 典型形态 | 为什么修 |
| --- | --- | --- |
| 误归属 | 拷贝或改写参考实现后，仍声明被审的 `backend_id` | agent 非恶意改动的真实形态 |
| 漏声明 | 未声明自己的 backend，却让清单出现被审模块名 | 同上 |
| 记录漂移 | 改了代码或 `reviewed_identities.json` 未同步 | 由测试强制，属可信度基线 |
| 虚假通过 | 声明的证据等级/资格与实际不符；报告与实测不一致 | 直接破坏结论可信度 |
| 读取端不一致 | 同一份包，不同读取入口（inspect / attest / postprocess / export）判定不一致 | 0.9.3 已修一处；此类会继续修 |

提报以上类别时请给出：复现命令或代码、受影响的证据等级（能否达到
`comparable`）、以及它是如何在正常使用中发生的。

## 3. 已冻结，不再修复也不再加强

以下各项**已知存在**，且**不会**再为它们增加检查。若提报，将按本文件关闭。

| 编号 | 绕过方式 | 为什么不再修 |
| --- | --- | --- |
| N1 | 对象级身份伪造的新变体：改写 `sys.modules` 命名空间绑定、`code.replace(co_filename=...)`、反射式替换方法 | 0.9.2 已封堵"`__module__` 指向被审模块"这一具体手法，但对象级溯源在 CPython 内无封闭解；继续追加检查是无穷枚举 |
| N2 | 进程内改写 `pe_sim.identity`、`pe_sim.artifacts` 等校验模块自身 | 同一双手既能改校验对象也能改校验器；这已不是"改动"，而是进程被接管 |
| N3 | 替换实例属性（`plant.step = ...`） | 对象由调用方提供，替换属性等价于换一个对象；内核只对"被交进来的那个对象"负责 |
| N4 | 无 `__code__` 的 C 层 callable（扩展模块、部分描述符） | 没有可比对的源文件，猜测比声明更糟 |
| N5 | 同时改写 solve-path 文件与 `reviewed_identities.json` | 摘要一致性检查无法分辨；由 Git 复核可见，属审查流程职责 |
| N6 | 直接编辑运行目录，并重算写回 `manifest.json` / `hashes`，使包重新自洽 | 这不是"包坏了"，而是"换了一个自洽的包"；由 attestation 锚定与 Git 时间线处理，运行时不判定 |
| N7 | 多进程并发追加 `anchor-index.jsonl` 无锁 | 项目不承诺多用户/多进程并发写；服务化阶段再引入锁 |
| N8 | 沙箱、签名、密钥、进程身份、SBOM 签名 | 属 Phase E / 产品阶段，不是内核职责 |

**重要说明:** N1–N8 不构成"防护失败"。它们是**已声明的边界**。本项目对外的
可信度依据是可重算的记录（摘要、清单、资格、审计流）加 Git 审查，而不是运行时
自我防卫。

## 4. 0.9.3 的读取端一致性保证

包自洽性规则（派生摘要汇总 + manifest/package 摘要重算）此前在 6 个读取入口各写
一遍，且覆盖已经漂移——`inspect-run` 曾接受一个 `hashes` 汇总被改过、而其他所有
入口都拒绝的包。

现在该规则只有一份实现：`pe_sim.artifacts.verify_package(manifest, run_dir) -> tuple[str, ...]`，
由发布前校验、`inspect_run`、`build_payload`、`load_run_evidence`、
`export_run_to_workbench_fixture`、复现性比较共同调用。新增读取端必须调用它，
不得自行实现较弱变体；`tests/test_package_integrity_consistency.py` 以同一份
篡改包对所有读取端做一致性断言。

## 5. 变更政策

1. 本文件是稳定期契约。新增任何**对抗性**防护，必须先修订本文件并注明它守的是
   §2 中的哪一类失败。
2. 已冻结项若因阶段推进变成真实需求（例如对外提供多用户服务），按新阶段
   （Phase E / 产品阶段）重新立项，不在内核里逐条打补丁。
3. 修复 §2 类缺陷时，必须同时给出回归测试；仅改代码不算修复。
