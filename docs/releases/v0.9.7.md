# v0.9.7 — Closure Classes and a Contract Budget

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

`docs/60` listed 35 scenarios but did not say *what it takes to close* each gap.
Without that, "does the architecture fit?" cannot be answered: an adapter gap and
a contract gap look identical in a status column, and every gap invites a kernel
patch.

## Changed

### 1. `docs/adr/0005` — two seams, no change to the existing three objects

The classification shows the architecture is broadly the right shape:

| Closure class | Rows |
| --- | --- |
| `closed` | 8 |
| `test-only` | 6 |
| `postprocess` | 2 |
| `adapter` | 6 |
| `controller` | 2 |
| `study` | 3 |
| `capability` | 3 |
| `kernel-impl` | 5 |
| `contract` | 1 |
| `never` | 1 |

Only **one** row needs a contract change, and ADR 0004 already decided it. Five
need kernel implementation without touching a protocol. The remaining 28 need an
adapter, a controller, a study, a post-processing metric, or a test.

The ADR therefore adds two seams rather than reworking `PlantAdapter`,
`ControllerAdapter`, or the Runner loop:

- **`Study` above the Runner**: parameter sweep, Monte Carlo, and brute-force
  periodicity (repeated transient until the trailing window is periodic). A
  study composes existing runs and never reaches inside the Runner; each
  constituent run keeps its own evidence level, and an aggregate does not
  inherit `comparable` automatically.
- **Optional model capabilities below the Plant**: `small_signal_model`,
  `loss_model`, `steady_state`. Absence is reported, never inferred — a plant
  that cannot linearize makes AC analysis unavailable, not `limited`.

Rejected deliberately: a vector actuator (scalar duty plus internal phase
management covers the common multiphase case; per-phase current sharing is
`specialized`), AC analysis inside the time loop, and thermal/device physics in
the kernel.

### 2. `docs/60` §2.2 — closure classes, as data

Each of the 35 rows is now classified exactly once, and two rules are stated:

- the `contract` class may not exceed **three** rows, and each such row must cite
  an ADR — growing the protocol requires a recorded decision;
- a `covered` row may not also be classified as needing kernel or contract work.

### 3. Two rows corrected by that rule

`A9` (dead time / synchronous rectification) and `B7` (multiphase) were marked
`out_of_scope` while their closure class was `adapter`. Both are closed by a new
adapter with zero kernel edits, so they are `expressible`; `out_of_scope` now
means only what ADR 0005 rejects (thermal in the kernel). The new consistency
test caught this; the matrix is the thing that was wrong, not the classification.

### 4. `tests/test_coverage_matrix.py` — four more guards

`test_every_row_has_exactly_one_closure_class`,
`test_the_contract_class_is_budgeted_and_cites_a_decision`,
`test_a_covered_row_is_not_blocked_on_work`,
`test_out_of_scope_rows_are_classified_never`.

## Not changed

- No runtime behaviour, no public API name; `pe_sim.__all__` is untouched.
- No scenario was implemented. `Study` and the optional capabilities are
  proposed, not built; `docs/60` still shows them as gaps.
- Study-level evidence vocabulary is deliberately deferred: until a study route
  exists, an aggregate must be presented as a set of per-run results.
