# v0.12.0 — Derived Metrics Without a New Evidence Level

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

`docs/60` rows C7 (ripple spectrum / THD / PF) and C10 (waveform export and
derived analysis artifacts) were the cheapest remaining "very common" rows: the
samples already exist, nothing about the solver needs to change, and the analysis
is a projection of one published package. They were `kernel_gap` only because no
module produced the projection.

The release also settles a vocabulary question that would otherwise leak into
every later study: **a derived artifact is not a new evidence level.** It is a
deterministic function of one run's samples; the run package remains the thing a
reviewer qualifies or rejects. A spectrum computed from a `limited` run is still
`limited` evidence.

## Changed

### 1. `pe_sim.derive` — standard-library spectral metrics

A new module, reachable as `pe_sim.derive` but **not** added to
`pe_sim.__all__` (the frozen stable surface is untouched). It uses only the
standard library, including a small radix-2 FFT, so the result does not depend on
an optional binary dependency.

| Function | Returns |
| --- | --- |
| `hann_window(n)` | periodic (DFT-even) Hann weights |
| `ripple_statistics(values)` | count, min, max, peak-to-peak, mean, RMS, AC RMS |
| `spectrum(times_s, values)` | one-sided Hann amplitude spectrum, resolution, peak frequency/amplitude |
| `thd(values, sample_rate_hz, ...)` | fundamental and harmonics 2..N, THD ratio |
| `power_factor(voltage, current)` | `mean(v*i) / (rms(v) * rms(i))` |
| `write_derived_report(run_dir, destination, ...)` | a linked JSON report and its digest |

Two normalisation details are documented in the module because they are easy to
get wrong and easy to over-claim:

- the window is periodic (`w[i] = 0.5 - 0.5*cos(2*pi*i/n)`), not symmetric, so an
  integer-cycle tone has no leakage into harmonic bins;
- zero padding puts most tones between bins, so the largest non-DC bin is refined
  by a golden-section maximisation of the direct DTFT around that bin. Without
  that step a 50 Hz tone on a 4096-point grid reads about 13% low.

### 2. The report states its own limits

`write_derived_report` writes `derived-report.json` with:

- `source`: `run_id`, `package_digest`, `manifest_digest` — the parent link;
- `method`: window, zero padding, resolution, normalisation, stored-bin limit;
- `limits.boundary_samples_only: true` — the package contains control-window
  boundary samples, not intra-switching waveforms; the report says so instead of
  letting a ripple number imply switching-level evidence;
- `limits.window_leakage: true` and the resolution in Hz.

The report **refuses** a destination inside the run package, **refuses** an
oversized report before writing anything (`max_bytes`, default 8 MiB), and
**refuses** a package that fails the existing integrity gate. The source package
is byte-identical before and after; the tests hash every file to prove it.

### 3. `docs/60` — C7 and C10 move to `covered`

Both cite the new test file. C10's evidence keeps `UD-03` visible: the package
still does not contain intra-window switching waveforms, and this release does
not pretend otherwise.

### 4. `tests/test_derived_metrics.py` — 11 tests

Frequency/amplitude recovery, THD of a pure and a distorted tone, exact ripple
statistics, power factor in phase and in quadrature, a real Buck package link
with unchanged bytes, destination and size refusals, a tampered-package refusal,
and input validation.

## Not changed

- No runtime behaviour and no public API name; `pe_sim.__all__` is untouched.
- No solve path changed; `backends/` and `reviewed_identities.json` are untouched.
- No claim about switching-level ripple: the report's `limits` says the samples
  are boundary samples.
