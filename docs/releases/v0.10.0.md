# v0.10.0 — Five Scenarios Proven Expressible, No Product Code Changed

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

`docs/61` puts the "test-only" rows first on purpose: they are the plan's own
self-check. If a row that `docs/60` calls *already expressible* cannot be proven
by a run-level test, then the classification is wrong and every later stage is
scheduled on a false premise.

The first execution of that check found one wrong row (`A6`, corrected in
0.9.8). The other five passed without touching product code.

## Changed

### 1. `tests/test_stage16_expressible_scenarios.py` — five run-level proofs

Each test asserts an observable result of a real `Runner` execution, not merely
that a call did not raise:

| Row | Scenario | What the test observes |
| --- | --- | --- |
| A3 | load step at a window boundary | the controller's `command` changes at the boundary window; `truth["load_resistance"]` changes at the next sample; `vout` falls |
| A5 | soft-start `vref` ramp | every scheduled reference reaches the controller in order; duty is non-decreasing and ends higher than it starts |
| B4 | sample / ZOH / computation delay | `timing["sample_offset_s"]` and `control_period_s` equal the timebase; `sample_time_s` equals window start + offset; the observed time agrees |
| B5 | feedforward | with zero error and `kp=ki=0`, duty equals `kff_v * vref`; the same zero error with `kp≠0, kff_v=0` yields zero duty |
| B6 | cascaded voltage/current loops | the outer loop's `current_reference` travels through `state_update` into the next step's `state`; duty rises with the reference |

These are expressibility proofs. They are not accuracy, precision,
switching-level, thermal, or hardware claims, and the module says so.

### 2. `docs/60` — five rows move from `expressible` to `covered`

A3, A5, B4, B5 and B6 now cite the test file that proves them. The `test-only`
closure class is empty; it stays in the table because the next row that turns out
to be expressible-but-untested belongs there.

A3's evidence also records the runner's schedule semantics, which are easy to
misread: the boundary window still observes the old load, because the new
scheduled input applies to the advance that follows the sample. The next sample
observes the new truth. That is a property of the design, not a defect, and it is
now pinned by an assertion.

### 3. `docs/61` — S1 recorded as delivered

The stage table now lists only open rows. Completed stages stay in place with an
empty row cell; their row ownership remains in `docs/60`'s evidence column and in
this note, so the ledger is still the thing a reviewer checks.

## Not changed

- No file under `src/` was modified by this release.
- No public API name; `pe_sim.__all__` is untouched.
- No new dependency.
