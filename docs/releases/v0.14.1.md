# v0.14.1 — Protection Is a Controller Wrapper, and Its Latency Is Declared

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

`docs/60` rows B9 (protection state machine) and A7 (short circuit / hiccup
recovery) did not need a kernel change. The controller protocol already sees the
same measurement the inner controller sees, and ADR 0004 step 2 already applies
a load change at its declared time inside a window. What was missing was the
state machine and a test with a real fault.

The honest part is the ceiling: protection is evaluated once per control sample,
so a fault is acted on in the **next control period**. This is not
cycle-by-cycle comparator hardware, and the release says so in the code, in the
manifest identity, and in `docs/58`.

## Changed

### 1. `ProtectionPolicy` and `ProtectedController`

A new module `pe_sim.protection` provides:

- `ProtectionPolicy`: optional `ovp_v`, `uvlo_v`, `ocp_a`; `trip_duty`;
  `hiccup_s` (`None` means latch); measurement keys; and a UVLO startup mask
  that keeps a cold start from tripping on its own zero output.
- `ProtectedController(inner, policy)`: a controller-protocol wrapper with three
  states:
  - `normal` — checks OVP, then OCP, then UVLO; on a fault it counts the trip
    and applies `trip_duty`;
  - `tripped` — holds the trip action for `hiccup_s` of control time, then
    retries the inner controller on that step; a persistent fault trips again;
  - `latched` — `hiccup_s=None`, no recovery.

Every `ActionRequest.state_update` carries `protection_state`,
`protection_trips`, `protection_elapsed_s`, and `protection_started`, so a run
trajectory can be audited without instrumenting the wrapper. The inner
controller's own `state_update` keys are preserved.

`snapshot()`/`restore()` keep the protection state and refuse a snapshot from a
different policy.

### 2. The ceiling is a declaration, not a footnote

`ProtectedController.declared_limitations` is
`("protection_latency_is_one_control_period",)`, and `manifest_identity()`
records it together with the policy and the inner controller identity. `docs/61`
§2.3 already registers that code for A7; `docs/58` now also says that
cycle-by-cycle comparator protection and peak current mode are not provided by
this route.

### 3. A7 acceptance uses a real fault

The Runner-level test drives a `BuckPlant` with 10 Ω → 0.2 Ω at 25 µs (inside a
control window) and back to 10 Ω at 75 µs:

- without protection, the current first exceeds 1.2 A at sample 6 (about 60 µs);
- with `ocp_a=1.2` and `hiccup_s=20 µs`, the action is the trip action from
  sample 6 onward, i.e. within one control period of the crossing;
- after the short is removed the wrapper retries at sample 8, the current is
  still above the threshold, and it trips again;
- the run finishes `QUALIFIED` with two recorded trips.

The test also asserts that samples before the fault are identical between the
protected and unprotected runs, so the trip is attributable to the fault.

## Not changed

- No kernel, plant, or adapter change; the wrapper composes through the existing
  controller protocol.
- No public API name changed; `pe_sim.__all__` is untouched.
- No cycle-by-cycle comparator claim. That remains `docs/60` B3/D3 and is routed
  to `docs/61` S9.
