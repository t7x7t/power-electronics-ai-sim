# v0.23.0 — Close the Refusable Gaps

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

Three independent audits of the agent-facing surface, the power-electronics
coverage and the extension points found that the substrate was sound but its
**refusals** were not: several paths could turn a wrong input into a plausible
answer. This release closes those, widens one vocabulary constraint that made a
legitimate converter inexpressible, and ships the reference designs the
authoring mode was missing.

## What changed in this release

### 1. A solver failure is not a request mistake

`simulate-topology` caught only `BackendProcessError`. `BackendTimeoutError` and
`NumericalNonconvergenceError` are its siblings, so a solver that ran out of
time or failed to converge escaped to the generic handler and was reported as
`CONFIG_REJECTED` / `invalid_request` with exit code 2 — telling an agent to
change its document when the document was fine. The command now catches
`SimulationExecutionError`, reports `status: "FAILED"` with the adapter's own
`category`, and exits 1. Request and document errors keep exit code 2.

### 2. A failed import writes nothing

`import-spice --output` wrote the descriptor whenever one had been produced, but
`ok` also requires the topology validator to pass. A netlist that translated but
described a disconnected graph therefore exited 2 *and* left a file behind.
Writing now requires `ok is True`, and the envelope carries no `output` key when
nothing was written.

### 3. A defaulted argument says so

`compile-topology` and `simulate-topology` default `--duty` to 0.5. A netlist
does not carry its pulse width (`docs/66`), so a 0.3-duty circuit compiled
silently at 0.5 while exiting 0. Both commands now report `duty_defaulted`,
`duration_defaulted` and `carrier_phase_defaulted`; behaviour and exit codes are
unchanged, but "I chose this" and "it was filled in" are no longer the same
output.

### 4. `validate` checks the controller surface

`validate` is the agent's inner loop, and it never looked at `controller_id` or
`controller_config`: a misspelled id passed with `ok: true` and only failed
later in `pe-sim run`. There is now a `controller` stage between `plant_config`
and `input_schedule`, with two closed codes:

- `unknown_controller` at `/controller_id`, with the registered ids as
  `expected` and a safe suggestion;
- `unknown_controller_config` at `/controller_config/<key>`, checked against the
  registration's own `config_keys`.

Three boundaries are deliberate. Only key names are checked: a registration
declares no value types, and inventing a second type table here would be a
private opinion about what a controller accepts. An empty registry means there
is no vocabulary to check against, so the stage does not run and `checked` omits
it rather than reporting "clean". And `collect_issues` still never loads the
composition root; `pe-sim validate` fills only the controller registry, which
builds nothing and creates no directory.

`REQUEST_REJECTION_CODES`, `SPEC_ISSUE_CODES` and `TOPOLOGY_ISSUE_CODES` are now
pinned by exact set equality rather than by count or subset, so a renamed code
cannot slip through.

### 5. A negative output rail is expressible

The load and the output capacitor accepted only `electrical` on their positive
terminal. Both are electrically symmetric, so which terminal is called positive
is a label — but the rule made an **inverting buck-boost** inexpressible: its
load and output capacitor sit between the reference node and a negative output
node. Both ports now accept `reference` too. Nothing else was relaxed: a
declared `voltage_v` is still non-negative, so a negative supply is still
reported as `invalid_parameter_value`.

### 6. Reference designs for the authoring mode

`examples/topologies/` now ships three complete descriptors — asynchronous buck,
synchronous buck with a declared complementary relation, and the inverting
buck-boost — each carrying the duty and duration that demonstrate its own
operating point in `metadata.example.compile`. They are data, not plants: no
registration, no solve path, no evidence claim. `tests/test_topology_examples.py`
validates and compiles every file, so an example that stops being expressible
fails the suite instead of the reader.

## Verified

- Full suite: every test green, including the ngspice-gated ones.
- The inverting buck-boost validates with zero issues and compiles to the
  expected seven cards, with the reference node bound by the load and the
  capacitor.
- A netlist whose translated topology has an isolated net exits 2 and writes no
  file.
- An injected `BackendTimeoutError` produces `status: "FAILED"`,
  `category: "backend_timeout"`, exit code 1.
- `--duty` omitted and `--duty 0.5` give the same netlist and different
  provenance flags.

## Known limitations

- `controller_config` **values** are still checked only when the controller is
  built; only keys are declared, so only keys are validated.
- The controller stage is silent when no controller registry is loaded. A
  library caller that wants the check must register its controllers first.
- The vocabulary still has eight device kinds, one carrier per actuator group,
  and no transformer, controlled source or behavioural source.
- Reference designs are examples, not evidence: a run over one is an inspection
  result at `limited`, never `comparable`.
