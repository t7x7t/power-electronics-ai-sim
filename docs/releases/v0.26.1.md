# v0.26.1 — The Import That Failed on Exactly One Interpreter Version

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

Every other defect closed in this series could be reproduced locally. This one
could not: it made `import pe_sim.spice_import` raise on Python 3.11 and on no
other version, so the project's own test interpreter (3.13) and its documented
verified pin (3.12) both passed while CI stayed red.

## 1. What was wrong

`ImportedNetlist` in `src/pe_sim/spice_import.py` declared four fields with a
shared read-only empty mapping as their default:

```python
net_name_map: Mapping[str, str] = MappingProxyType({})
```

`dataclasses` refuses a field default it considers mutable, and *how* it
decides that changed:

| Interpreter | Check | `mappingproxy` | Result |
| --- | --- | --- | --- |
| 3.10 | narrower list/dict/set test | unhashable | accepted |
| 3.11 | `type(default).__hash__ is None` | **unhashable** | **`ValueError: mutable default`** |
| 3.12+ | same check | hashable (it gained `__hash__`) | accepted |

So the failure window was exactly one minor version. On 3.11 the module could
not be imported at all, which turned into 35 collection errors and a red
`contract` job; on 3.10, 3.12 and 3.13 the same code was fine.

## 2. What changed

- The four fields now use `field(default_factory=_empty_read_only_map)`. Each
  instance gets its own read-only empty mapping, which is strictly safer than
  sharing one, and the module imports on every supported version.
- No public name, refusal code, schema tag, or descriptor shape changed. This
  is a defect fix, not a contract increment.

## 3. The guard that would have caught it

`tests/test_full_module_scan.py` gained a fifteenth test,
`test_no_dataclass_default_is_one_python_311_would_reject`. It walks every
dataclass the package defines and restates the 3.11 rule in a
version-independent form: a field default must never be a `mappingproxy`, and
must never be an instance of an otherwise unhashable type. Because it checks
the *shape* of the default rather than replaying 3.11's check, it fails on
3.12 and 3.13 too — the interpreters where the original bug was invisible.

## 4. Evidence

The 3.11 run used an interpreter built from the same `requirements-tested.txt`
pins the CI job installs:

```text
Python 3.11.18
pytest -q --collect-only  ->  2090 tests collected
pytest -q                 ->  2059 passed, 31 skipped in 238.96s
```

Before the fix the same environment reported `35 errors during collection`
and `Interrupted: 35 errors during collection`, matching the CI job's exit
status.

On the development interpreter (3.13.2):

```text
pytest -q tests/test_full_module_scan.py  ->  15 passed
```

## 5. What this note does not claim

A green matrix is not a release. The formal gate chain, the distribution
inventory, the release record, human approval and the tag remain separate
artifacts (`docs/29`, `docs/53`), and none of them was produced for this
version.
