# v0.21.0 — Complementary Gates and Compiled-Circuit Execution

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## What changed in this release

### 1. A declared relation between gate signals

A descriptor may now state how several gate signals derive from the one duty
ratio the kernel commands:

```json
"metadata": {
  "control": {"mode": "single_duty_complementary", "dead_time_s": 1.0e-7}
}
```

The compiler maps that to the timing the reviewed synchronous reference already
renders explicitly:

- high side on `[0, D*Tsw - dead_time]`;
- low side on `[D*Tsw, Tsw - dead_time]`;
- both gates low during the two dead-time intervals.

The classification uses connections, not names: the switch whose conducting
path reaches the reference net is the low side. Two switches sharing one gate
net, a missing carrier on either gate net, a dead time at or beyond half a
switching period, or carriers declaring different frequencies are refusals, not
guesses.

Two refusal codes were added, bringing the closed set to 16:
`invalid_control_declaration` and `ambiguous_complementary_control`.

The shipped synchronous-Buck descriptor now declares the relation, so its two
gate nets no longer produce a `multiple_control_nets` warning: the document
explains itself. The validator and compiler share the mode vocabulary through
a test that pins the two sets equal.

### 2. The switch gate references its own driver

The `S` element's control reference is now the negative node of the carrier that
drives the gate, not an unconditional node 0. A floating or high-side gate drive
is a legal circuit; comparing its gate voltage against ground made every card
look legal while the control relation was wrong.

### 3. `CircuitPlant`: execute a compiled topology

`src/pe_sim/backends/circuit_plant.py` is new. It is a stepped Plant adapter
over one descriptor:

- one constant-duty netlist per control window, rendered by `compile_topology`;
- the next window resumes from the previous endpoint's inductor currents and
  capacitor voltages (`initial_conditions`), with the segment-start carrier
  phase;
- external `vin_v` / `load_ohm` updates become per-window
  `parameter_overrides` instead of rewriting the descriptor;
- `vout` is the voltage across the single `resistor_load`, so a floating load is
  measured correctly;
- `snapshot` / `restore` carry element state only; resumed runs are
  state-equivalent, not bit-identical in general.

The adapter registers its solve path at runtime. `reviewed_identities.json` is
unchanged, so its review status is `not_pinned` and every result is capped at
`limited` evidence.

### 4. The netlist and the manifest carry the same solver settings

`CircuitPlant` derives `.options`, `method`, `set numdgt`, and `.temp` from its
`NgspiceSolverSettings`. The `integrator` constructor argument is an override of
`integration_method`, applied to the settings object itself. A manifest can no
longer report a tolerance or integration method the netlist did not contain.

### 5. `pe-sim simulate-topology`

```text
pe-sim simulate-topology <topology.json> \
  --duty 0.5 --duration 1e-3 [--step S] [--control-period S] \
  [--carrier-phase S] [--integrator trap|gear|euler] [--timeout S] \
  [--ngspice PATH] [--output-dir DIR]
```

It validates, compiles, and solves one open-loop window through the reviewed
ngspice process boundary. Success prints a `pe-sim.topology-simulation.v1`
report with bounded per-signal summaries; `--output-dir` also writes
`simulation.json` and `pe-sim.topology-samples.v1` samples. Request, document,
and compile problems keep the existing rejection envelope; a solver failure is
reported as `status = "FAILED"`. Sample export is capped at 2,000,000 points
and refuses rather than truncating.

## Measured acceptance

- Compiled complementary netlist vs `render_sync_buck_netlist`, 120 µs window,
  phases 0, 3 µs, 6 µs: final-window mean `vout` and `i(L1)` agree within 1e-3.
- Compiled asynchronous Buck vs `NgspiceBuckPlant`, 20 ms: final `vout` agrees
  within 1e-3, and with `D*Vin` within 0.15 V.
- Two 1 ms windows vs one 2 ms window: final `vout` agrees within 1e-4.
- `snapshot → restore → next window` vs the continuous next window: identical
  `vout` and `iL` to every printed digit.
- `simulate-topology` with a missing executable returns the rejection envelope
  with `reason = "backend_not_found"`; with a real solver it writes the report
  and samples and exits 0.

## Known limitations

- The reviewed synchronous reference does not model a body diode. During the
  dead time the inductor current is interrupted, so that model does not settle
  to `D*Vin`; `CircuitPlant` reproduces the reviewed model, it does not repair
  it. A descriptor may add an explicit `freewheeling_diode` to provide the
  path.
- `CircuitPlant` is not registered as a built-in Plant yet, so `pe-sim run` and
  `pe-sim study` cannot select it by `plant_id`; the closed loop still needs a
  controller acceptance and a nested `plant_config.topology` schema.
- Only `single_duty_complementary` is understood. Interleaving, multiphase
  relations, and three-level timing are not.
- No subcircuits, `.include`, controlled sources, or SPICE-subset import
  (Step C).
