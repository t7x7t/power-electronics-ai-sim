# v0.14.0 — Controllers Are Registered, and Type II/III Are Explicit

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

`docs/60` row B2 asked for a Type II/III compensator on the kernel side, but the
blocker was not the compensator: `controller_id` was a schema enum
(`["pi", "pid"]`), the CLI had a hardcoded binding table, and the schema owned
the configuration key set. Adding a compensator meant editing three places, and
a third party could not add one at all.

This is the same "enumerated capability" problem ADR 0004 removed from plants.
ADR 0007 applies the same answer to controllers.

## Changed

### 1. `controller_id` is resolved, not enumerated

- The schema accepts the same safe identifier grammar as `plant_id`.
- `controller_config` is an object; the per-controller key set belongs to the
  registration, not to the schema.
- `pe_sim.controller_registry` mirrors the plant registry:
  `ControllerRegistration`, `register_controller`, `resolve_controller`,
  `registered_controllers`, `clear_controllers`.
- `resolve_controller` rejects an unknown id or an undeclared key **before a run
  directory exists**, and names the registered ids in the error.
- The CLI no longer has a binding table; it resolves through the registry.

### 2. One explicit difference equation

`DiscreteCompensator` (order 1–3) applies:

```text
y[n] = b0*x[n] + b1*x[n-1] + ... - a1*y[n-1] - a2*y[n-2] - a3*y[n-3]
```

with `x = vref - measurement`. There is no hidden integrator. When the output
saturates, the delay line stores the **applied** (clamped) value, so the
compensator cannot keep accumulating an action the actuator never executed.

### 3. Type II/III are Tustin designs over that law

- Type II: `K (1 + s/wz) / (s (1 + s/wp))`, second order.
- Type III: `K (1+s/wz1)(1+s/wz2) / (s (1+s/wp1)(1+s/wp2))`, third order.

The coefficients are computed at the control period, stored as public design
attributes, and appear in the controller identity in the manifest. A run states
the exact discrete law it executed. `biquad` exposes `b0,b1,b2,a1,a2` directly
for users who design coefficients elsewhere.

### 4. Built-ins and compatibility

Registered built-ins: `pi`, `pid`, `type2`, `type3`, `biquad`.

`pi` and `pid` keep the same implementation and the same key sets; their numeric
behaviour is pinned by the existing tests. A PID configuration copied onto `pi`
still fails, because the registration declares its keys.

### 5. Two tests updated to match the new contract

- `test_controller_id_remains_a_closed_enum` becomes
  `test_controller_id_uses_the_same_identifier_contract_as_plant_id`.
- The PID schema test now checks that the schema accepts a safe id and that the
  **factory** rejects a negative filter constant, instead of expecting the schema
  to do both.

These are contract changes, recorded in ADR 0007, not weakened assertions: the
rejection moved to the layer that owns the value.

## Not changed

- The controller protocol (`observe`/`reset`/`snapshot`/`restore`) is unchanged.
- No public API name changed; `pe_sim.__all__` is untouched.
- No solve path changed; `backends/` and `reviewed_identities.json` are untouched.
- B9 (protection state machine) and A7 (short-circuit fault injection) are still
  open. They build on this registry and on the change-point support from 0.13.
