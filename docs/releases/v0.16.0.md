# v0.16.0 — Capability Analysis Has an Entry Point

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

The capability seam (ADR 0005, Seam 2) had a working library — analytic
small-signal models, Tustin loop gain, impedance/Middlebrook, and a declared
loss model — but no user-reachable entry. `docs/60` therefore kept C4, C5, and
C6 at `kernel_gap`: a function nobody can call is not a supported capability.

This release adds one entry point and hardens the evidence rules underneath it.
The entry point is deliberately **not** a study kind: a study composes ordinary
runs, while a capability analysis asks one declared model a frequency- or
loss-domain question at one explicit operating point.

## Changed

### 1. `pe-sim capability` and `pe-sim.capability-analysis.v1`

`pe-sim capability CONFIG` reads a standalone document:

```json
{
  "schema": "pe-sim.capability-analysis.v1",
  "analysis_id": "buck-ac",
  "kind": "ac",
  "plant": {"id": "buck", "config": {}},
  "operating_point": {"duty": 0.5, "input_voltage_v": 48.0, "load_resistance_ohm": 10.0},
  "sweep": {"start_hz": 10.0, "stop_hz": 100000.0, "points": 241},
  "controller": {"id": "type2", "config": {}, "control_period_s": 1e-4},
  "output": {"directory": "capability-out"}
}
```

- `kind: "ac"` returns a plant Bode sweep, and — when `controller` is declared —
  the Tustin loop gain and stability margins.
- `kind: "impedance"` returns a `Zin`/`Zout` sweep and, when `external` is
  declared, the Middlebrook magnitude screen.
- `kind: "loss"` returns the declared loss breakdown. `lossy-buck` is a
  capability-only plant declaration; it is not registered as a runner plant.
- The report is `pe-sim.capability-report.v1`, printed as JSON and atomically
  written to `output.directory/capability-report.json` when an output directory
  is declared. Every nested result keeps its own `provenance`.

### 2. Study evidence integrity

The study layer now records `execution_ok` / `analysis_ok` / `failure_reason` /
`exit_code` per point. `cross_point_comparability="claimed"` requires every
point to succeed; a non-zero executor exit, a bad manifest, a failed statistic,
a periodicity error, or unreadable/non-finite samples all fail the point even if
a stale `QUALIFIED` package exists on disk. Manifest `run_id`, `plant.id`, and
`manifest_sha256` are checked, and `package_sha256` is verified with the
existing `verify_package` rule. Point configs are written atomically.

### 3. Capability semantics

- `stability_margins` treats `+180°` and `−180°` as the same direction; a phase
  that stays flat there reports `gain_margin_db=None` plus
  `phase_flat_at_minus_180` instead of inventing a margin from the first sample.
- `middlebrook_ratio` rejects negative magnitudes and invalid frequency axes;
  `NaN`/`inf` magnitudes remain `not_evaluable`.
- `LossBreakdown` rejects negative output power/efficiency and a
  `declared_lossless=True` breakdown with non-zero terms or efficiency ≠ 1.
- `CapabilityUnavailable` reasons are a closed set; the CLI maps them to the
  existing `invalid_request` rejection envelope with a `reason` field.
- A caller factory cannot declare `origin="builtin"`; only the project-owned
  factories may.

### 4. Public surface

The new study/capability names are reachable from `pe_sim` as **experimental**
names. `pe_sim.__all__` is 344 names (81 stable + 263 experimental); the frozen
stable list is unchanged.

## Limits (unchanged)

- AC/impedance results are analytic CCM averages at a declared operating point;
  they do not model sampling delay, ZOH phase, or aliasing.
- Middlebrook is a necessary magnitude screen, not a stability proof; there is
  no phase-margin form.
- Loss terms are averaged, fixed five-term approximations; no ripple correction,
  core loss, or temperature dependence.
- Capability results never carry an evidence level. They are not run evidence.
