# v0.17.0 — Adapter Expansion: Switching Modes and Model-Side Control

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

`docs/60` still listed four adapter-class rows that could not be expressed by
the existing registrations: a synchronous-rectifier template, a switching-level
whole-run trace, a controller that closes the loop inside the model, and a
cycle-by-cycle peak-current comparator. This release adds them as **new
registrations**, not as flags on existing adapters and not as kernel branches.
The kernel keeps the same `PlantAdapter` / `WholeRunPlant` protocols; T1 ("new
engine, zero kernel edits") remains true.

## New registrations

### A9 / A8 — `ngspice-sync-buck`

`backends/sync_buck.py` renders `ngspice-sync-buck-v1`: high-side and low-side
ideal switches, explicit gate PWL sources with dead time on both transitions,
no freewheeling diode, arbitrary segment-start carrier phase, and a per-cycle
conduction-regime classifier (`ccm`, `dcm`, `forced_ccm`, `idle`, `burst`).
The DCM/burst labels are observations with explicit thresholds, not burst-mode
control.

### B7 — `multiphase-buck`

`multiphase_plants.py` models 2–8 averaged phases that share one duty command.
The integrated state is the total inductor current; per-phase currents are an
equal-share declaration. `per_phase_current_sharing_not_modelled` is part of
the identity; per-phase current loops, phase shedding, and ripple cancellation
are not claimed.

### A11 / B8 — `whole-run-switching-buck` and `model-control-buck`

`backends/model_control_buck.py` contains one deterministic switching core used
by two registrations:

- `model-control-buck` is a `stepped + model` adapter. The kernel still owns
  the clock and observes every window, but the PI loop is inside the model.
  The kernel-provided action is recorded in truth (`kernel_action_ignored`) and
  deliberately not applied.
- `whole-run-switching-buck` is a `whole_run + model` engine. It integrates the
  complete horizon with switching-edge splitting and returns a declared-cadence
  trace with ripple. The kernel can only validate the trace after the fact.

Both declare `actuator_control_in_model`; the whole-run route additionally
declares `in_run_enforcement_unavailable` and `post_hoc_validation_only`. Both
are capped at `limited` by the existing single `RouteCapabilities` derivation.

### B3 / D3 — `peak-current-buck`

The same switching core exposes a fixed-frequency peak-current mode. The outer
voltage PI produces a current reference in amperes; the model computes the
high-side on-time to reach it from the inductor current at the cycle start and
records the comparator event time. `diode_emulation=True` additionally records
the zero-crossing event and holds the inductor current at zero until the next
clock. There is no blanking time, propagation delay, slope compensation, or
current-sense filter; comparator and diode events are model-internal and the
route remains `limited`.

## Evidence and public surface

- New solve paths are registered at runtime with `register_solve_path`; no
  reviewed-identity pin was edited. Formal comparison remains capped at
  `limited` until a maintainer records a review.
- The new classes and topology descriptors are exported through the
  **experimental** public surface only. The stable list is unchanged.
- `docs/60` A8/A9/B7/A11/B8/B3/D3 are `covered`; `docs/58` and `docs/61`
  describe the remaining limits.

## Limits

- The Python switching core is an ideal state-space reference: no dead time,
  body diode, switch capacitance, ESR/ESL, magnetic saturation, loss, or
  thermal model.
- The model-side PI is a reference controller, not a tuned or deployable
  compensator. The kernel cannot shape its actuator.
- Peak-current on-time uses the cycle-start linear inductor slope; the
  comparator and diode events are model-declared, not kernel-enforced.
