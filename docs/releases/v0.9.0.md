# v0.9.0 — Text-First Run Review and End-to-End Flow Check

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

The withdrawn browser workbench proved that a graphical first version made the
reading order ambiguous: identity, claim, parameters, checks, and provenance
were all available as JSON, but nothing told a reader what to look at first.
This release makes the hierarchy the product and keeps graphics out.

## What changed

### `pe-sim review-run` — text-first hierarchical review

- New `pe-sim.run-review.v1` envelope with eight fixed sections in a fixed
  order: integrity, claim, parameters, checks, signals, provenance, artifacts,
  limitations.
- New `pe-sim review-run <run> [--format text|markdown] [--json]`. The default
  output is an ASCII-only text report, so a legacy Windows console cannot mangle
  it. No box-drawing characters, no colour, no Unicode arrows.
- Each section carries a status (`ok`, `attention`, `fail`, `unavailable`), and
  a row whose own status is not `ok` is marked in place. Finding groups are
  capped at 20 rows with an explicit "N more" note so the hierarchy stays
  readable; the full findings remain in the manifest and `inspect-run`.
- Signals are summarised as text rows (`n`, `min`, `max`, `mean`, `last`). No
  waveform is drawn.

### Read-only service

- `GET /v1/runs/{run_id}/review` returns the rendered text by default,
  `?format=markdown` returns markdown, and `?format=json` returns the envelope.
  The route is read-only and revalidates the package per request.
- Discovery adds `inspection_schemas.review`. The three visualization contracts
  and `contract_schemas` are unchanged.

### End-to-end flow check

- New `scripts/full_flow_check.py` with contract
  `pe-sim.full-flow-check.v1`: environment → capabilities → agent surface →
  configure → run → debug → inspect → review → export → service → audit →
  compare.
- It writes only under `.tmp/full-flow/<timestamp>`, installs nothing, and uses
  no network. Required steps must pass; skipped optional steps make the outcome
  `partial`, which exits `2` and is not a pass.

## Non-claims

- The review reorders and labels recorded facts. It adds no evidence, changes no
  verdict, and approves nothing. A section marked `attention` or `fail` does not
  change `evidence_level`, `qualification_level`, `credibility`, or the claim
  conclusion.
- No chart, topology drawing, waveform plot, dashboard, or interactive control
  is delivered. Trace samples remain available through `TraceDataset` for a
  later UI, which must render the review envelope rather than invent a parallel
  model.
- The flow check is a smoke check of the documented path, not a release gate,
  not a physical validation, and not a substitute for
  `scripts/release_check.ps1`.
- No parameter range, physical validity, thermal, safety, or hardware claim is
  added.
