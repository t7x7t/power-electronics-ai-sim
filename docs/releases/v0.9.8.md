# v0.9.8 — A Sequenced Closure Plan, and One Ledger Correction

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

`docs/60` records 26 open operating conditions and `docs/43` records the
architecture phases, but neither answers "in what order do we close the 26, and
when is one of them done?". Without that, every gap is equally urgent, the
cheapest work (proving an existing capability) competes with the most expensive
one (a new analysis type), and a gap can stay open across releases with nobody
noticing.

## Changed

### 1. `docs/61_gap_closure_plan_v1.md` — the closure sequence

Eleven stages, each independently shippable, each with a closure layer and a
gate. Every open row is assigned to exactly one stage. The plan also states what
"closed" means: `covered` with a test reference, or `out_of_scope` with a
recorded decision — never a permanent `expressible`.

Two rules in the plan are worth quoting because they constrain this work:

- **Evidence ceilings are declared.** A row that cannot reach `comparable` must
  record its ceiling and the limitation code that explains it (`limited`,
  `per-point`, `inherit`, or `functional`). A row that runs but does not say how
  far it can be trusted is not closed.
- **No product-level surface before S10.** Visualization extensions and new
  Workbench panels stay out of scope until the ledger has no open rows.

### 2. `docs/60` §4 — one sequencing authority

The five-line ordering that used to live in the ledger is removed; it now points
at `docs/61`. Two documents with two orders is how a project ends up with a
"current priority" that changes with the reader.

### 3. One ledger correction: A6 is not `test-only`

The plan's first stage exists to test the classification itself, and it caught a
wrong row. `A6` (pre-biased start) was marked `expressible`, on the assumption
that `initial_state` could carry `vout`. It cannot:

- `InitialState` has three fields (`mode`, `snapshot_path`, `snapshot_hash`) and
  `to_dict()` returns exactly those;
- the JSON schema permits additional properties, so a document with
  `initial_state: {"mode": "warm_start", "vout": 5.0}` validates;
- `ExperimentSpec.from_dict` then calls `InitialState(**dict(initial))` and
  raises `TypeError` — or, if the field were dropped, would start cold and look
  normal.

That is a contract gap, not a missing test. `A6` is reclassified from
`test-only` to `contract`, the closure plan gains an early stage for it (S3),
and `docs/adr/0006-initial-state-payload.md` records the decision.

### 4. `tests/test_coverage_matrix.py` — five more guards

The plan is now checked by the same module that checks the ledger:

- `test_the_plan_is_present_and_has_stages`;
- `test_the_plan_assigns_every_open_row_to_exactly_one_stage` — the set of
  `expressible` / `kernel_gap` rows must equal the union of the stages, with no
  row scheduled twice;
- `test_stages_are_numbered_and_versioned_in_order`;
- `test_every_stage_declares_its_layer_and_its_gate`;
- `test_the_evidence_ceiling_register_names_rows_that_exist` — the ceiling column
  uses a closed vocabulary (`comparable`, `limited`, `functional`, `per-point`,
  `inherit`).

A plan that silently drops a gap now fails a test, which is the only reason to
write the plan as a table instead of prose.

## Not changed

- No runtime behaviour and no public API name; `pe_sim.__all__` is untouched.
- No scenario was implemented. S1 onwards build on this plan; the first
  deliverable is a set of run-level tests for rows the kernel already supports.
- `docs/57`'s frozen bypass surface and the reviewed identity pin are untouched.
