# v0.16.1 — Capability Report Write Failures Are Branchable

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

A post-release, interface-only end-to-end exercise ran the capability entry on
a realistic 48 V → 12 V / 5 A buck operating point and on the rejection matrix.
The analyses themselves were correct, but one output path was not: when
`output.directory` existed and the atomic write failed at `open`, `fsync`, or
`os.replace`, `write_capability_report` let the bare `OSError` escape. The
generic CLI handler then emitted a `CONFIG_REJECTED / invalid_request` envelope
with no `reason` field, so a client branching on `reason` lost the documented
`output_error` signal.

## Changed

- `write_capability_report` now wraps every write-phase `OSError` (open, flush,
  fsync, atomic replace) as `CapabilityAnalysisError("output_error", ...)`.
- Temporary-file cleanup is best-effort and can no longer mask the primary
  write failure.
- The CLI rejection envelope for this path now carries
  `error_code="invalid_request"` and `reason="output_error"`, matching the
  existing contract used when `mkdir` itself fails.

## Verification

- `tests/test_capability_cli.py` — **11 passed**, including a regression that
  makes `capability-report.json` a directory so `os.replace` fails, and a new
  real-operating-condition end-to-end test covering `ac`, `impedance`, and
  `loss` at one 48 V → 12 V / 5 A point with artifact/hash/provenance checks.
- Interface-only rejection matrix: 26 enumerated cases pass (exit code 2,
  single strict-JSON envelope, stable `error_code`/`reason`, no partial
  artifacts).
- Positive interface matrix: 54 assertions, 51 pass; the 3 non-passes were
  test-harness expectation errors, not implementation defects (open-loop
  `Zin(0)=+R/D²`, the lossy model's self-consistent operating point, and
  `input_sha256` covering the whole input document including `output`).

## Limits (unchanged)

- AC/impedance results remain analytic CCM averages at a declared operating
  point; they do not model sampling delay, ZOH phase, or aliasing.
- `middlebrook` remains a necessary magnitude screen, not a stability proof.
