# v0.15.0 — Studies Are Plans over Ordinary Runs

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

Three rows in `docs/60` needed orchestration *above* a single run and nothing
below it: A10 (input/load/duty sweeps), C9 (Monte Carlo / tolerance / worst
case), and C3 (periodic steady state). ADR 0005 already decided the shape — a
`Study` composes runs that already exist and never reaches inside the Runner.
What was missing was the layer itself.

The interesting constraint is not the looping. It is that a study makes an
**aggregate** claim, and this repository has exactly one evidence ladder with
exactly one producer of route caps. So the release's job was to add the
orchestration without inventing a new evidence level or letting a summary
borrow strength from its best point.

## Changed

### 1. `pe_sim.study` — the planning rules

A stdlib-only module that owns expansion, sampling, statistics, the periodicity
test, the aggregate rule, and the report. It does not import the runtime, the
CLI, or a solver.

- `parse_study_document` validates `pe-sim.study.v1` with closed key sets and
  expands it into **ordinary experiment documents**, one per point. Each point
  gets its own `run_id` (`<study_id>-pNN`) and a shared `<output>/runs`
  directory, and each expanded document is re-validated through the experiment
  schema before anything runs.
- `parameter_sweep`: 1–3 parameters × 2–16 values, cartesian, capped at 64
  points. A path must already exist in the base document, must be a numeric
  leaf, and may not name `schema_version`, `run_id`, `output`, or
  `experiment_id`.
- `monte_carlo`: `uniform`/`normal` parameters with an explicit seed. Draws
  consume only `random.Random(seed).random()`; the normal transform is the
  module's own Box–Muller, so the sequence does not depend on a Python
  implementation detail. The report records every draw and a canonical
  `draws_sha256`.
- `periodicity`: the seam's brute-force PSS. Each point lengthens the transient
  by `duration_s × extend_factor^k`; within a point the trailing windows are
  compared pairwise at a lag of `compare_period` control periods.
- `statistics_for_point`: `mean`, `min`, `max`, `rms`, `peak_to_peak`, `last`,
  and `ratio_of_means` over recorded samples.

### 2. `pe_sim.study_runner` and `pe-sim study`

The runner writes `<output>/points/pNN/config.json` **before** each point runs,
delegates execution to an injected callable, and reads `manifest.json` /
`samples.json` back from the published package. It knows nothing about plants,
controllers, or backends, so the same code runs under fakes in tests.

`pe-sim study CONFIG` takes the same option set as `pe-sim run` (`--backend`,
`--mode`, `--applicability`, `--no-standard-qualification`, `--ngspice`,
`--model-builder`) and adds no new mode or flag. Parsing and the per-point
preflight — including the `formal_comparison` + `whole_run` refusal — happen
before any directory is created, so a plan that cannot run leaves nothing
behind.

### 3. The aggregate never inherits `comparable`

`aggregate.evidence_level` is the literal string `per-point`. The aggregate also
reports:

- `inherited_ceiling`: the weakest level any point actually published;
- `point_evidence_levels`: counts per level, with `undeclared` for a point whose
  manifest carries no recognised level (which is treated as
  `diagnostic_only`, not as missing);
- `cross_point_comparability`: `claimed` only when every point is `QUALIFIED`,
  every point is itself `comparable`, and all points share the same `run_mode`,
  `plant.id`, and route triple — otherwise `not_claimed` with codes from a
  closed set;
- `limitations`, always including `aggregate_does_not_inherit_comparable`.

Per-point `status`, `evidence_level`, and `manifest_sha256` are read from the
point's own `manifest.json`. The study layer re-derives no evidence level and
recomputes no digest.

### 4. C3 acceptance, and what it does not claim

On the averaged reference buck (`kp = 0.02`, `vref = 5 V`, base duration 2 ms,
`extend_factor = 8`) the third point (128 ms) converges: worst trailing-window
relative difference `2.0e-7` against a `1e-4` tolerance, and an independent
re-evaluation of that run's `samples.json` reproduces the number.

Two honest limits came out of building it:

- **A proportional loop plus a `duty ∈ [0, 1]` clamp sustains a relay-type
  limit cycle.** At `kp = 0.2` the overshoot drives the duty to zero, the
  plant can only discharge through the load, and the trailing-window difference
  was still about `1.4e-2` after 1.02 s of simulated time (index lag 1), four
  orders of magnitude above the `1e-4` tolerance. That is a property of the
  scenario, not of the study layer, and picking a gain that never reaches the
  clamp is part of writing an honest convergence acceptance.
- **`periodicity` is a tolerance statement.** It declares
  `pss_convergence_is_tolerance_based` and reports the per-point numbers even
  when the study ends without converging (exit code 1, report still written).

### 5. What this release deliberately does not do

- **No efficiency or loss claim.** The stage's acceptance text mentioned an
  efficiency curve; power and loss decomposition belong to C6, which is
  `docs/61` stage S8 and needs an optional `loss_model()`. A sweep therefore
  produces **descriptive sample statistics**, and every study carries
  `descriptive_statistics_only_no_loss_claim`.
- **No public API growth.** `pe_sim.study` and `pe_sim.study_runner` are not
  re-exported from the package top level — the same choice as `pe_sim.derive`
  and `pe_sim.protection`. `tests/fixtures/public_api.json` and
  `pe_sim.__all__` are unchanged.
- **No new rejection codes, no new modes, no kernel edits.** The CLI maps a
  malformed study document to the existing `invalid_request` code, and every
  point is executed by the existing `run` path.

## Independent audit and corrections

An independent reviewer audited the stage read-only against ADR 0005, `docs/61`
§3, and the coverage ledger. It returned **FAIL**, and the failures were real:

1. **A repeated parameter path silently collapsed an axis.** Writing
   `controller_config.kp` twice in `parameter_sweep.parameters` produced four
   points for two distinct experiments, and four records is exactly what
   `cross_point_comparability` counted — so a study could claim cross-point
   comparability with duplicate points. The same bug let a second `normal`
   distribution overwrite a first `uniform` one in `monte_carlo` while the plan
   still listed both. A path may now appear **once** per plan
   (`duplicate_parameter_path`), and `claimed` additionally requires unique
   `run_id`/`index` and non-empty identity strings (`duplicate_points`,
   `point_identity_incomplete`).
2. **An unreadable package still exited 0.** A corrupt `manifest.json`, a
   manifest whose `status` was `FAILED`, or a missing `samples.json` for declared
   statistics all left the point recorded with `status: null` and the study
   exiting 0. Each now fails the point through `details.manifest_error` /
   `details.statistics_error`, publishes the report anyway, and exits 1.
3. **A finite but huge `sigma` produced an infinite draw.** The plan accepted
   `sigma = 1e308`, the experiment schema accepted the resulting `inf`, and the
   config writer raised a bare `ValueError` after seven of eight point
   directories had been created. Draws are now validated at plan time
   (`invalid_draw`), and `config.json` is written **per point, immediately before
   that point runs** — so a failed plan leaves no directory and a converged
   `periodicity` study leaves no config for points it skipped.

Smaller corrections that came out of the same audit: `run_study` no longer takes
an `output_dir` override (the only output root is `plan.output_dir`), the report
temporary name carries the process id, `evaluate_periodicity` reports
`sampling_interval_s` and documents that `compare_period` is an index lag over
`compare_period × compare_windows + 1` trailing samples, and an empty study
reports `empty_study` rather than `single_point_study`. Two pre-existing
assertions had to change with the closed reason set — both are recorded in
`docs/61` §2.2 S7.

## Verification

- `pytest` without `PE_SIM_NGSPICE`: **1450 passed, 11 skipped**.
- `pytest` with the reviewed ngspice executable: **1459 passed, 2 skipped**
  (both skips are the optional `PySpice` extras).
- `tests/test_study_plan.py`: 122 tests — document grammar, expansion budgets,
  path rules, sampling determinism, reducers, periodicity evaluation, and the
  aggregate rule in both directions, plus the adversarial cases the audit added
  (duplicate paths, overflowing draws, duplicate records, blank identities, and
  the `empty_study` / `single_point_study` split).
- `tests/test_study_runner.py` (19) + `tests/test_study_cli.py` (9): an
  unreadable manifest, a `FAILED` manifest, missing samples under declared
  statistics, an executor that raises while later points still run, a config that
  cannot be serialized, configs written only for executed points, a sweep over
  `plant_config.load_resistance_ohm`, an independent re-evaluation of the
  periodicity comparison, a Monte Carlo check that the point parameters equal the
  published draws, and a `formal_comparison` + `whole_run` study rejected before
  any run.
- `tests/test_coverage_matrix.py`, `tests/test_public_api.py`,
  `tests/test_version_consistency.py`, `tests/test_release_policy.py` pass with
  `docs/60` A10/C3/C9 moved to `covered` and the `study` closure class emptied.
