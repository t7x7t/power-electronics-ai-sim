# v0.9.4 — One Run-Id Rule, Visible Declaration Errors

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

Two independent findings, both in the categories `docs/57` §2 says will be
fixed: a reader/writer disagreement, and a malformed declaration that was
reported as sound.

## Fixed

### 1. The write path accepted run ids the attestation path rejected

`validate_run_location` only rejected empty ids, `.`/`..`, separators, and
`..`. `attestation._validate_run_id` additionally rejected Windows reserved
device names and a trailing dot or space. Consequence:

- `run_id = "CON"` (also `AUX`, `NUL`, `PRN`, `COM1`…`COM9`, `LPT1`…`LPT9`)
  created a formal Buck run that reached `QUALIFIED` and
  `evidence_level: comparable`, while its package could never be attested — L1
  was unreachable by construction.
- `run_id = "trailing."` landed in `runs/trailing` because the filesystem
  strips the dot, while `manifest.json` recorded `run_id = "trailing."`: a
  silent directory/record drift.

Both sides now call one rule, `pe_sim.artifacts.validate_run_id`, and the write
side applies it before any directory is created. `attestation._validate_run_id`
delegates to it and keeps its own error type, and the duplicated
`_SAFE_RUN_ID` / `_WINDOWS_RESERVED` constants are gone.

The experiment schema is deliberately unchanged: `tests/test_plant_id_schema.py`
requires `run_id` and `plant_id` to share one schema definition, and the runtime
validator is the authoritative gate either way.

### 2. A malformed parameter declaration was inferred into `declared`

`normalise_parameter_provenance` treated the declared `status` as a hint:

- an unregistered token such as `"trusted"` fell through to inference and
  became `declared` with `declaration_error: null`;
- `ParameterRecord.__post_init__` silently replaced a NaN, an infinity, a
  string, or a bool with `None`, so an explicit `status: "declared"` survived
  and the applicability summary still said `within`.

`docs/40` §2.1 requires a malformed declaration to become
`declaration_invalid` with a bounded error, without crashing the run. Now:

- an unregistered status token returns `declaration_invalid` naming the token;
- `ParameterRecord` raises `ValueError` instead of coercing, so the invalid
  state is unrepresentable; `normalise_parameter_provenance` turns that into
  `declaration_invalid` rather than letting a bad value disappear;
- `None` remains legal — it means "value not known" and still yields `partial`;
- `declaration_error` is bounded to 200 characters, because an adapter can
  raise an arbitrary message.

A malformed declaration is still non-blocking by design (`docs/40` line 241):
it is now *visible* — `parameter_provenance_status` becomes
`declaration_invalid`, a `provenance.declaration.invalid` finding is recorded,
and the summary can no longer read `within`.

## Not changed

- No new module and no new public API name; `pe_sim.__all__` is untouched.
  `validate_run_id` is a module-level function, not an export.
- The declared-vs-inferred rule for an *absent* status is unchanged, including
  the `partial` result for explicit `None` values.
- Nothing in `docs/57` §3 was defended: no new adversarial check was added.

## Verification

- `tests/test_run_id_consistency.py`: 15 passed. Both sides are asserted to
  reject the same ids and accept the same ids, and a `CON` / `trailing.` run is
  asserted to fail before any directory exists.
- `tests/test_parameter_provenance_validation.py`: 10 passed. Unregistered
  token, NaN/Inf/string/bool values, explicit `None`, direct record
  construction, adapter error collection, and summary visibility.
- Both files failed before the change (20 failures; the summary printed
  `assert 'declared' == 'declaration_invalid'`).
- Full suite: 1122 passed, 7 skipped.
