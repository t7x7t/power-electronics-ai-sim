# v0.9.1 — Evidence-Trust Fixes

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

An independent review found that the trust root for formal evidence could be
bypassed. Three defects let a run reach `evidence_level: comparable` while the
code that produced the samples was not the reviewed implementation, or while the
package named a model that never ran. All three are fixed here, with regression
tests that reproduce the bypass.

## Fixed

### 1. Adapter identity compared only a file name (`identity.py`)

`verify_adapter_identity()` matched `Path(inspect.getfile(cls)).name` against the
declared solve-path module names. A file named `reference_plants.py` anywhere on
`sys.path` therefore passed every check: digest, review status, and location are
all inherited from the real `manifest_identity()`.

Reproduced before the fix: a subclass in `.tmp/forge_p01/reference_plants.py`
with `observe()` forced to `vout = 123.456` reported `verification: verified`, and
a `formal_comparison` run reached `QUALIFIED` / `comparable` / `assessed`.

Now the adapter class file is resolved and compared with the resolved declared
solve-path files; a same-named file elsewhere is rejected even when its content
is byte-identical. The verification block records `module_path` as a
package-relative path (or `null` outside the package) and `solve_path_files` as
declared relative paths, so the manifest stays portable and contains no
machine-specific absolute path.

### 2. The Python API skipped document and adapter validation (`contracts.py`, `runtime.py`)

`run_experiment()` is a facade over `Runner.run()`, and the CLI's protections
were only in the CLI.

- `ExperimentSpec.from_dict()` now runs `validate_experiment_document()`, so an
  unknown `input_schedule` key such as `v_ref` is rejected instead of being
  silently ignored while the controller keeps `vref = 1.0`.
- `Runner.run()` cross-checks an adapter that publishes `manifest_identity`
  against its registration before any directory exists: a **verified** adapter
  must run under its registered `plant_id`, with the registered class name and
  time model. Pairing `plant_id="ngspice-buck"` with the averaged `BuckPlant`
  is now rejected instead of publishing `comparable` evidence labelled
  `ngspice-buck`.
- Unknown schedule keys are rejected for any registered plant.
- Deliberate boundary: an adapter that does **not** verify (a subclass or a
  plugin) keeps the library freedom to vary a reference model; it cannot reach
  `verified` and is capped at `limited`. `PlantRegistration.backend_id` (the
  `--backend` adapter name) is not compared with a plant's `backend_id` (its
  solve-path key); they are different concepts.

### 3. The flow check failed when its output was outside the repository (`scripts/full_flow_check.py`)

`attest-run` correctly refuses to anchor an attestation record stored outside the
Git repository. The check passed `--repo` unconditionally, so an output
directory outside the repository turned the `audit` step into a failure, even
though `docs/56` states the check writes only under `--output`.

The check now chooses the mode by containment: anchored when the attestations
directory is inside the repository, `--no-anchor` plus an explicit limitation
when it is outside. A failure in that step now means the command genuinely
errored.

### 4. The text review could be injected with control characters (`review.py`)

`render_text()` and `render_markdown()` wrote recorded strings verbatim, so a
newline in a parameter name, artifact path, or run id could inject a fake section
header or a fake `claim:` line into the one surface a human reads. Both renderers
now escape `\`, `\n`, `\r`, `\t`, and every other C0 control character (plus
`\x7f`) before rendering. The JSON envelope keeps the raw recorded strings;
output is byte-identical when no control character is present.

## Documentation

- `docs/43` records the T5 regression and the 0.9.1 tightening instead of
  claiming an unbroken pass.
- `time_model.py` no longer says the whole-run route is unimplemented; it exists
  since 0.5.10 and is capped at `limited`.
- `docs/56` describes the anchored and unanchored audit modes.

## Non-claims

- No sandbox, no signature, no authentication. A process that can rewrite the
  installed package can still rewrite the check.
- A local writer can still replace a package between verification and reading;
  `inspect-run` and `review-run` document that they are not a sandbox.
- An unverified adapter may still run, but it cannot reach `comparable`.
