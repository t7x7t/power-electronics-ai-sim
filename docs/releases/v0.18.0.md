# v0.18.0 — Closure and Evidence Alignment

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## What changed in this release

### 1. `event_granularity=window` is a controller statement

After ADR 0004 step 2, every solve segment ends at the next declared input
change point and the external input is resolved at the segment start. A
`window` registration therefore does **not** quantise the plant input to
control-window boundaries. What remains of `window` is the controller side:
observation and actuation still happen only at window boundaries, and the
registration declares no cost for in-window events. The limitation code
`events_quantized_to_control_windows` is consequently a controller-side
statement, not a plant statement.

Evidence: `tests/test_event_granularity_semantics.py` runs a mid-window input
change against a boundary change on the pure-Python `buck` registration and
pins that the two runs differ. If a later change makes `window` really quantise
the plant input, the runs become identical and the test fails; such a change
must also update `docs/58` and ADR 0004. README, `docs/58`, ADR 0004,
`docs/61` (S2) and the `time_model` / `plant_registry` docstrings now say the
same thing. No runtime behaviour changed.

### 2. Provenance records the version of the running code

`environment.runner.version` used to be read from the installed distribution
metadata, which an editable checkout can leave stale. It is now taken from
`src/pe_sim/_version.py` — the code that is actually running. The installed
metadata is recorded beside it as `package_metadata_version`; when the two
disagree, the run appends the limitation

```text
installed distribution version differs from the running code version
```

instead of silently reporting stale metadata.

Evidence: `tests/test_provenance_version.py` covers metadata lag, matching
metadata, and missing metadata. No run behaviour and no evidence-level
derivation changed.

### 3. All schemas ship with the package

`src/pe_sim/schemas/` now contains all five repository schemas:

- `experiment.schema.json`
- `manifest.schema.json`
- `stage10-evidence-report.schema.json`
- `stage10-metrics.schema.json`
- `stage12-evidence-classification.schema.json`

Previously only `experiment.schema.json` was packaged, so an installed package
could write documents it could not validate. Evidence:
`tests/test_packaging.py` asserts that every `schemas/*.json` file is present in
the package, reachable through `importlib.resources`, and byte-for-byte
identical to the repository copy.

### 4. Catalog fields and small correctness fixes

- `plant_catalog` now exposes `control_location` and `event_granularity` for
  every registration; `docs/44` documents the fields. Evidence:
  `tests/test_plant_registry.py`.
- `ac_analysis` dropped a local `_finite_number` helper that shadowed the import
  from `frequency_domain`; the single imported validator is used. Evidence:
  the existing `tests/test_ac_analysis.py` is unchanged and passes.
- `runtime._derive_evidence_level` dropped an unreachable `"limited"`
  qualification branch; the qualification vocabulary is
  `assessed` / `partial` / `failed`. Behaviour is unchanged.
- A stale `public_api` comment was corrected: the whole-run route is
  executable and capped at `limited`, not "declared but not implemented".
