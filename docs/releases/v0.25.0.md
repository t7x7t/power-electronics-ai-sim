# v0.25.0 — Interleaved Gates, and a Scan of the Whole Package

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

Two things happened in this release. The authoring layer learned the second of
the two gate relations it can render, which makes multiphase DC-DC expressible
rather than merely compilable. And the package got a scan that treats "the parts
still form one whole" as a property to test, which is what turned up most of the
defects fixed here.

## What changed in this release

### 1. `single_duty_interleaved`

A descriptor can now declare that one commanded duty drives N gates spread
evenly across the switching period:

```json
"metadata": {
  "control": {"mode": "single_duty_interleaved", "phases": 3}
}
```

Phase *k* of *N* first fires at `k·Tsw/N`; every phase keeps the same on-width,
because the kernel commands one duty ratio and splitting a phase would be
splitting the command. `gate_order` (optional) is the firing order, so an author
who cares which leg leads says so instead of reading it back out of a sorted
list. The compiler reports the resolved `gate_first_rise_s` and `phases` in
`CompiledCircuit`, in the `compile-topology` summary, and in the
`simulate-topology` `netlist` block.

`examples/topologies/interleaved_buck.json` is a three-phase interleaved buck
with per-phase freewheeling diodes. Measured on ngspice (D = 0.5, Vin = 12 V,
100 kHz, 200 µs window, pre-charged):

```text
gate_first_rise_s: pwm_1=0.000 µs  pwm_2=3.333 µs  pwm_3=6.667 µs
solved rising edges: pwm_1=0.001 µs  pwm_2=3.334 µs  pwm_3=6.667 µs
observed duty:       0.500964       0.502891        0.498160
v(vout) mean:        5.9247 V       (D·Vin = 6.0 V)
```

### 2. Six defects that independent audits found, in the order they mattered

1. **Zero duty rendered a pulse.** The width had a `1e-15 s` floor so that a
   `PULSE` card never had a zero width. That is a turn-on the author did not
   command, and the compile record then had to report a first rising edge for a
   gate that never conducts. `duty = 0` now renders `DC 0` and reports no rise.
2. **`phases` said 2 for a complementary pair.** A synchronous buck reported
   `phases: 2`, which reads as "two interleaved legs". A pair of gates on one leg
   is one phase; the field now says so.
3. **A parameter override reached nothing.** `switching_frequency_hz` was
   white-listed for `parameter_overrides` but the period, width and phase were
   read from the raw component, so overriding the frequency changed nothing and
   reported nothing. The carriers are now read through the override view.
4. **Two dead times could disagree silently.** `pulse_source.dead_time_s` is
   recorded, and `metadata.control.dead_time_s` is rendered. A carrier stating a
   different value left the author believing a number that the netlist does not
   contain; the compiler now refuses the disagreement.
5. **The compiler rendered a port on a net kind its device rejects.** The
   compiler promises it can be called without the validator. A resistor load
   wired to a control net therefore rendered as a perfectly legal `R` card, and
   every other card looked fine. It now repeats that check.
6. **Any mode string silenced a warning.** `validate-topology` stopped warning
   that several control nets have no stated relation as soon as `metadata.control`
   contained *any* known mode, including `{"mode": "single_duty_interleaved",
   "phases": 4}` on a three-net graph. A declaration that does not fit the graph
   is now reported as a declaration that does not fit, not as silence.

### 3. The vocabulary no longer refuses the reference terminal on one side

`voltage_controlled_switch.input`, `inductor.input`/`output` and
`freewheeling_diode.cathode` accepted only `electrical`. A low-side switch is
naturally drawn `gnd → node`, and `import-spice` preserves SPICE node order, so
an imported synchronous rectifier produced a descriptor that the project's own
validator rejected with `port_net_kind_mismatch`. The conducting path is
two-terminal and the element card is symmetric; both ends may now bind the
reference, exactly as `capacitor`, `resistor_load` and `freewheeling_diode.anode`
already could.

### 4. `describe-devices` stops borrowing the `validation` key

Its refusal filled `validation` with `pe-sim.circuit-devices.v1`, while
`docs/45` states that `validation` is always `pe-sim.spec-validation.v1`. Both
envelopes carry an `issues` array, so a client that branched on `validation` to
pick a parser would have parsed a device vocabulary with a spec parser and got a
wrong answer without an error. The key is now `issues_schema`.

### 5. Two documents that close silent gaps

- **`docs/68_envelope_registry_v1.md`** lists every `pe-sim.<name>.vN` tag the
  source writes, with the module that produces it. 15 of the 41 tags had no
  document at all before this release, which meant an agent could not know which
  parser an envelope needed.
- **`docs/69_scope_boundaries_v1.md`** states what the substrate deliberately
  does not express — magnetic coupling, switch reverse recovery, nonlinear
  magnetics, thermal networks, sinusoidal and three-phase sources, multi-leg
  independent control, per-period multi-pulse modulation, static gate levels,
  paired complementary legs, PSS/sweep analysis, built-in current-mode
  controllers, and any UI — and for each one names the refusal an author will
  actually see plus the nearest honest substitute.

### 6. `tests/test_full_module_scan.py`

A scan over the package rather than over one behaviour. It links:

- **modules to an inventory.** Every module in `src/pe_sim` is listed. Adding one
  fails the scan until someone writes its name down, which is the moment to ask
  whether an authoring module just acquired a solver dependency.
- **modules to their import-time dependencies.** No module imports a third-party
  package at import time, and only five pinned composition roots import
  `pe_sim.backends` at import time. Parsing a descriptor must never require a
  simulator.
- **codes to the refusal vocabulary.** Every public `*_CODES` set is pinned, and
  every overlap between two independent vocabularies is recorded with its reason.
- **tags to documentation.** Every schema literal in the source appears in the
  envelope registry, and the registry names nothing the source does not write.
- **commands to documentation.** Every subcommand the parser accepts is mentioned
  in the README or the docs, and every subcommand can describe itself.
- **links to files.** Every Markdown link in the README and the docs resolves.

## Evidence

The full suite is **2061 passed / 2 skipped** with `PE_SIM_NGSPICE` set. The scan
itself is 14 tests and runs in about 2 seconds.

The two skipped tests are the ones that need a solver build the environment does
not have (see `docs/08`); they skip loudly rather than pass silently.

## What this release does not change

`pe_sim.__all__`, `REQUEST_REJECTION_CODES` (still 6), `plant_catalog()` keys,
`time_model.py`, `reviewed_identities.json`, and the `CIRCUIT_COMPILE_CODES`
vocabulary (still 16) are unchanged. `TOPOLOGY_ISSUE_CODES` is unchanged at 26.
The visualization surface is untouched.
