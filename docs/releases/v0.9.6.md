# v0.9.6 — A Machine-Checked Coverage Ledger

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

Two gaps were reported in sequence — an intra-window load step, and a control
period that may not be an integer multiple of the switching period — and both
were already described in the repository (`UD-05`, the `min_switching_periods`
numerical limit, the `constant duty ratio within each solved control window`
assumption). They were not *unknown*; they were **unsequenced**, and the only
way to find them was to read adapter docstrings and validity envelopes.

The architectural gates (`T1`-`T7` in `docs/43`) verify properties of the
architecture. None of them answers "is this common operating condition
supported". That is the defect this release addresses: not a missing feature,
but a missing ledger.

## Changed

### 1. `docs/60_simulation_coverage_matrix_v1.md`

A 35-row matrix of operating conditions across four groups — time-domain
scenarios, control structures, analysis types, and numerical/time-scale
requirements — with a closed status vocabulary:

| Status | Means | Requires |
| --- | --- | --- |
| `covered` | works today | names the test file that proves it |
| `expressible` | kernel can express it; adapter/controller missing | says what is missing |
| `kernel_gap` | needs a new kernel capability | a backlog id, GAP id, ADR, or document |
| `out_of_scope` | declared not to be built | the document that decides it |

It also has a "silent gap" section for conditions that today return a
plausible-looking result without warning, and a self-held gap register
(`GAP-01` AC loop gain, `GAP-02` impedance scan, `GAP-03` efficiency and loss
breakdown) for gaps that had no backlog entry at all.

Findings worth recording: no AC/loop-gain, PSS, FFT/THD, efficiency, thermal,
Monte Carlo, or impedance capability exists anywhere in `src/pe_sim`; and no
test exists for soft start, pre-biased start, a Runner-level load step, short
circuit, DCM/light load, dead time, overcurrent protection, thermal, AC,
efficiency, tolerance sweep, or multiphase.

### 2. `tests/test_coverage_matrix.py`

The ledger is checked by tests, so it cannot rot silently:

- status, frequency, owner, and expressibility use closed vocabularies;
- row ids are unique and grouped;
- a `covered` row must reference an existing `tests/...py` file that actually
  contains tests;
- a `kernel_gap` row must name a backlog id, GAP id, ADR, or document;
- an `out_of_scope` row must name the document that decides it;
- every very-common scenario that is not covered must have a registered gap;
- every registered GAP id must be referenced by a row;
- the matrix must not shrink below 30 rows.

Consequence: claiming coverage now requires evidence. Adding a row is cheap;
claiming `covered` without a test fails CI.

## Not changed

- No runtime behaviour, no public API name; `pe_sim.__all__` is untouched.
- No scenario was implemented in this release. The matrix is the prerequisite
  for sequencing, not the implementation.
- `docs/57` §3 non-goals are unchanged; none of them was defended.

## Verification

- `tests/test_coverage_matrix.py`: 40 passed (35 rows plus five structural
  checks).
- Full suite: 1170 tests. One run reported
  `test_visualization_service.py::test_path_traversal_unknown_route_and_write_are_rejected`
  failing with `ConnectionAbortedError` (a local socket reset); the module
  passes 10/10 in isolation, and this change touches no service code.
