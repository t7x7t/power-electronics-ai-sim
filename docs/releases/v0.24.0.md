# v0.24.0 — Measure Performance From the Waveforms

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

The authoring mode is "the user and an agent write the circuit; the project
supplies the substrate". Under that split, shipping a loss model per converter
would put topologies back into the kernel. What generalises is a **measurement**,
and that is what this release adds.

## What changed in this release

### 1. `pe_sim.waveform_metrics`

Given a compiled descriptor and the samples of one solved window,
`waveform_metrics` reports input power, load power, the stored-energy rate, the
loss between them, efficiency, the observed duty, inductor current statistics
and per-signal summaries. Nothing in it names a converter: the same code answers
for a buck, an inverting buck-boost, or a circuit this project has never seen.

The energy balance is

```text
input = output + d(stored energy)/dt + loss
```

measured on every sample of the window. `docs/67` describes the definitions and
the measurements behind them.

### 2. The stored-energy term is not optional

A window that starts with an uncharged capacitor absorbs joules that would
otherwise be reported as loss. In the 20 ms startup window measured during this
release, leaving the term out turns 0.43 W of capacitor charging into "loss":

```text
input=4.65857 W  output=4.28584 W  storage=0.426902 W  loss=-0.0541685 W
```

### 3. Omissions are reasons, not zeros

- **Efficiency is withheld** unless the stored-energy rate is at most 5% of input
  power. A startup transient has no operating-point efficiency, and computing one
  would dress a transient up as a metric. The `reason` names the storage share
  and says to solve a longer or periodic window.
- **A missing signal is `null` plus a reason**, never `0 W`. Reporting zero for
  "no source current was saved" is indistinguishable from measuring zero.
- **A negative loss is reported, not clipped.** It means the sampled model
  dissipated less than nothing — trapezoidal ringing at switching instants — and
  `quality.loss_is_physical` says so.
- **No single reference net means no power at all**: `ok: false` and a reason,
  because terminal voltages are undefined.

### 4. The sign convention is calibrated

`i(V...)` in ngspice is positive into the source's positive terminal, so
delivered power is `-v*i`. That is pinned by a test against a real solve rather
than asserted in a comment: `i(v1)` reads −0.388 A at `v(vin)` = 12 V, giving
4.659 W, which closes the balance.

### 5. The compiled netlist now saves every source current

`circuit_compile` saves `i(<element>)` for each independent source, alongside
every non-reference net voltage and every inductor current. Without it input
power cannot be measured at all. `i(V2)` is the gate-drive current and is
reported separately; with the ideal switch model it measures zero.

### 6. `simulate-topology` reports the numbers

The `pe-sim.topology-simulation.v1` report gains a `metrics` block. Its failure
classification is now the adapter's own `category` rather than a hardcoded one,
so a timeout says `backend_timeout`.

## Verified

- Synthetic tables: `input = output + storage + loss` holds exactly, a charging
  capacitor is excluded from loss, and missing signals surface as reasons.
- A real solve: raising the switch on-resistance from 1 mΩ to 0.5 Ω raises the
  measured loss monotonically from −0.050 W to +0.057 W, and the identity still
  holds on the measured values.
- The observed duty reads 0.49956 for a commanded 0.5.
- The import round trip still reproduces every element and model card byte for
  byte; only the order of saved vectors differs, and the solved rows still agree
  point for point.
- Full suite green including the ngspice-gated tests.

## Known limitations

- One window, not steady state. Every number integrates that window; a window
  that has not reached periodicity measures a transient, which is why efficiency
  is withheld rather than estimated.
- Loss is a total, not an attribution. Splitting it into switch, diode and
  magnetics terms needs per-device currents, and building those per topology is
  the thing this layer avoids.
- Inductor `peak_to_peak` includes startup inrush and switching-instant spikes,
  so it is not steady-state ripple.
- These numbers do not raise the evidence level: they are `limited`, like every
  other result from a caller-authored topology.
