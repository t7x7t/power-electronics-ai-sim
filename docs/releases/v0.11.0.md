# v0.11.0 — Initial State Carries a Bounded, Verifiable Payload

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

A pre-biased start is an ordinary operating condition: a hot-plug, a restart
without discharge, a sequenced rail. The reference plants and the ngspice netlist
could already express it, but the experiment document could not carry the value.

The gap was silent in the worst way: the JSON schema permits additional
properties, so `initial_state: {"mode": "warm_start", "vout": 5.0}` validated —
and then `ExperimentSpec.from_dict` raised `TypeError` on the unknown keyword. A
document that looked accepted could not run, and a variant that dropped the field
would have started cold while looking normal. `docs/60` listed the row as
"expressible"; the first stage of the closure plan proved otherwise and
reclassified it.

## Changed

### 1. `InitialState.state` — a bounded payload

`InitialState` gains `state: Mapping[str, float] | None`.

| Rule | Value |
| --- | --- |
| entries | at most 16 |
| key length | 1–64 characters |
| key grammar | the existing safe identifier grammar (no separators, whitespace, `.`/`..`) |
| reserved keys | `mode`, `snapshot_path`, `snapshot_hash` are rejected |
| values | finite real numbers; `bool` rejected |
| ordering | frozen and sorted at construction |
| combinations | rejected with `qualified_snapshot` |

The payload is frozen into a read-only, sorted mapping, so two documents that
differ only in key order produce the same digest and the same manifest.

### 2. Two shapes, on purpose

- `to_dict()` is the document/manifest shape: the payload stays nested under
  `state`. Without a payload the output is **byte-identical to before** — no
  `"state": null` appears, so existing manifests and checkpoint hashes do not
  change.
- `reset_arguments()` is the plant/engine shape: the payload is flattened to the
  top level, because `PlantAdapter.reset` and the whole-run engine read state
  fields directly.

### 3. The plant must echo what it applied

The kernel does not know plant state names (I5). After `reset()`, every requested
key must appear in the returned mapping with the same value. A key the plant
ignores fails the run **before the first observation or advance** — a cold start
that silently ignores a pre-bias would otherwise look qualified.

Runs without a payload are untouched: no check, no new branch.

On the whole-run route the engine already validates its `initial_state` keys
strictly against an allow-list, so an unsupported key fails there for the same
reason. The route passes the flattened form; the nested `state` never reaches the
engine.

### 4. Manifest records the payload and its digest

`manifest["initial_state"]` gains `state` and `state_sha256` **only when a payload
exists**. The digest covers the sorted payload and nothing else, so a reader can
verify it without re-running the plant.

### 5. Schema documents the payload

Both copies of `experiment.schema.json` (packaged and repository) gain the `state`
property: object of numbers, at most 16 properties, safe key pattern, and a rule
that a `qualified_snapshot` cannot also carry a payload. The change is additive;
the schema version remains valid because the property was already permitted by
`additionalProperties`.

### 6. `tests/test_initial_state_payload.py`

32 tests: the pre-bias acceptance, manifest digest and absence cases, the
echo failure path, construction-time rejection (including the reserved keys),
schema acceptance/rejection, and a document round-trip.

## Not changed

- No solve path changed: `backends/` and `reviewed_identities.json` are untouched.
- No public API name changed; `pe_sim.__all__` is untouched.
- No other `docs/60` row changed status in this release.
