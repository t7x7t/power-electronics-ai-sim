# v0.10.1 — Route Capabilities Are Declarations, the Cap Is Derived

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

ADR 0004 step 1. Two facts about a solve route were implicit and therefore
invisible in the manifest:

- whether the closed loop closes in the kernel or inside the model, and
- whether an external input may change between observation points.

Both are independent of `time_model`, and the evidence cap is a consequence of
the first two, not a third opinion. Making the facts explicit *before* removing
any restriction is what keeps step 2 from becoming a patch: S4 deletes an
assumption, it does not add a mode.

This release is deliberately behaviour-neutral. No run produces different
samples than it did in 0.10.0.

## Changed

### 1. `RouteCapabilities` — three declarations, one refusal

`pe_sim.time_model` now defines `CONTROL_LOCATIONS = ("kernel", "model")` and
`EVENT_GRANULARITIES = ("window", "continuous")`, plus a frozen
`RouteCapabilities(time_model, control_location, event_granularity)` record.

`whole_run + kernel` is refused **at construction**: if the model owns the clock,
there is no per-window executor for the kernel to drive. The same refusal happens
at plant registration and before any run directory is created, because both paths
build the same record.

### 2. One table, one derivation

The evidence cap lives in exactly one module-private table keyed by
`(time_model, control_location)`:

| time_model | control_location | cap |
| --- | --- | --- |
| `stepped` | `kernel` | `comparable` |
| `stepped` | `model` | `limited` |
| `whole_run` | `model` | `limited` |

A test lowers that table at runtime and observes the manifest level drop to
`limited`. A local copy in the runtime would keep the run at `comparable`, so the
test fails if anyone reintroduces one.

The historical one-field helpers (`evidence_cap`, `cap_evidence_level`,
`route_limitations`, `formal_comparison_allowed`) keep their exact call shapes and
values; they delegate with the reading that was always implied (a `whole_run`
route holds the compensator in the model).

### 3. Manifest reports the declarations

Every run manifest gains:

```json
"route": {
  "time_model": "stepped",
  "control_location": "kernel",
  "event_granularity": "window",
  "evidence_cap": "comparable",
  "limitations": ["events_quantized_to_control_windows"]
}
```

The limitation codes are composed in a stable order: route-inherent, then the
control declaration (`actuator_control_in_model`), then the event declaration
(`events_quantized_to_control_windows`).

The existing `time_model` and `route_limitations` keys keep their previous values
exactly. Whole-run manifests still report only the two inherent limitations under
`route_limitations`; the complete list is under `route.limitations`. That split is
deliberate: old readers keep working, new readers get the full declaration.

Note that a stepped route now *reports* `events_quantized_to_control_windows`.
That code describes the current design honestly — inputs resolve once per control
window — and it is the code S4 removes when change-point segmentation lands.

### 4. Built-in plants declare what they do today

| Plant | time_model | control_location | event_granularity |
| --- | --- | --- | --- |
| `buck`, `boost`, `ngspice-buck` | `stepped` | `kernel` | `window` |
| `whole-run-buck` | `whole_run` | `model` | `window` |

The declarations are explicit in `builtin_plants.py`, not inherited from defaults,
so the manifest cannot drift away from the code by accident.

### 5. `tests/test_route_capabilities.py` — 16 tests

Covers the cap table, the construction refusal, closed vocabularies, stable
limitation order, backward compatibility of the four legacy helpers,
registration-time refusal, refusal before filesystem work, two real runs
(`buck`, `whole-run-buck`) and the single-table proof.

## Not changed

- No scenario was closed. `docs/60` statuses are unchanged by this release.
- No solve path changed: `backends/` and `reviewed_identities.json` are untouched,
  so `ngspice-buck` remains `reviewed`.
- No public API name changed; `pe_sim.__all__` is untouched. The new names are
  module-level in `pe_sim.time_model`, and the record is not re-exported at top
  level.
