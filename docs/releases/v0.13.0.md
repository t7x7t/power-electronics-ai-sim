# v0.13.0 — Phase-Continuous Windows and Change Points Inside a Window

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

Two of the remaining `docs/60` rows were not missing features but wrong
assumptions:

- **A4**: a load step inside a control window was pushed to the next window
  boundary, and the resulting curve still looked smooth. That is the silent-gap
  class: the run did not fail, it answered a different question.
- **D2**: the control period had to be an integer multiple of the switching
  period, because every window netlist restarted the PWM carrier at zero.

Both were implementation choices, not physics. ADR 0004 step 2 removes them by
making the carrier phase a parameter and ending a solve segment at the next
input change point.

## Changed

### 1. Carrier phase is a solve-segment parameter

The netlist template is now `ngspice-buck-v2`:

```text
.param TD=<delay>
Vpwm pwm 0 PULSE(0 1 {TD} 1e-9 1e-9 <pulse_width> {Tsw})
```

`delay` is `(-phase) mod Tsw`, where `phase = segment_start mod Tsw`. The delay
is the time to the **next** absolute carrier start, not the phase itself. The
ADR's original wording (`TD = phase`) only happens to be correct when a segment
starts at zero or half a period; a segment starting at 7.5 µs of a 10 µs period
would have started its pulse at 15 µs, i.e. 5 µs late. The formula and the ADR
text are corrected together.

Consequence: `control_period_s` may be any positive duration. The constructor
no longer requires an integer multiple, and the `uncheckable_rules` entry that
stated the restriction is gone.

### 2. A solve segment ends at the next change point

`_advance_segments` now resolves the external input per segment instead of once
per control window:

- it finds the next `input_schedule` time in `(segment_start, segment_end)`;
- it ends the solve segment there and resolves `vin`/`load`/`vref` again at the
  new segment start;
- control observations and actions remain window-boundary events. The event
  granularity changes *when inputs change*, not when the controller runs.

The adapter still solves to the end of the current control window, never past
it. A change point inside the window invalidates the cached table naturally,
because the inputs no longer match.

### 3. `ngspice-buck` declares `event_granularity = "continuous"`

The registration now says what the adapter actually does. When a Python caller
omits the declaration, `Runner.run` takes it from the registration for the same
`time_model`, so the manifest cannot understate a reviewed capability. An
explicit caller declaration still wins.

### 4. The review pin carries the change

`backends/netlist.py`, `backends/ngspice_plants.py` and
`backends/netlist_builder.py` are on the reviewed solve path. The pin is updated
with:

- new `implementation_sha256`:
  `200a29788392d2b3b94a9401655e6faf79de95b060fbed8ca282bd1bb4dc7b4e`;
- acceptance id `event-boundary-acceptance`;
- evidence references to ADR 0004 and `docs/61`;
- a review note that names the phase formula, the removed restriction, the
  segment-end rule, and what was *not* touched (device models, solver settings,
  process invocation, wrdata parsing).

### 5. `tests/test_event_boundaries.py`

- the netlist renders the segment-start phase as a delay (always runs);
- **D2**: eight 1.5-period windows agree with one direct run over the same
  interval, which a restarting carrier could not do;
- **A4/D3**: a mid-window 10 Ω → 5 Ω step differs from the same step at the
  window boundary, in the expected direction, and agrees with the same change
  resolved inside one long control window;
- the registration and manifest declare `continuous`.

The two ngspice tests are opt-in via `PE_SIM_NGSPICE`, like the rest of the real
backend acceptance suite.

## Not changed

- Duty is still zero-order-hold within a solve segment; the controller still
  runs once per control window.
- Comparator-level events (peak current mode) are **not** implemented. `docs/60`
  keeps D3 open for that part and routes it with B3 to `docs/61` S9. No text in
  this release should be read as a cycle-by-cycle protection claim.
- No public API name changed; `pe_sim.__all__` is untouched.
