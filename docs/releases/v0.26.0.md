# v0.26.0 — Paired Legs, and a Warning Before a Silent Flat Line

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

The authoring layer could already render one leg's two gates from one duty
(`single_duty_complementary`) and N evenly spaced single gates from one duty
(`single_duty_interleaved`). The composed case — several legs, each
complementary inside itself, sharing one duty and separated by a phase shift —
had no declaration, so the only way to compile it was to describe it as
something it was not. This release adds that declaration, and adds the one
validation check that says "this switch can never conduct" while the author is
still editing, instead of after a solve returns a plausible flat line.

## What changed in this release

### 1. `paired_complementary`

```json
"metadata": {
  "control": {
    "mode": "paired_complementary",
    "pairs": [["high_1", "low_1"], ["high_2", "low_2"]],
    "dead_time_s": 1e-07,
    "leg_phase_shift_s": 5e-06
  }
}
```

`pairs` is required: each two-element entry is one leg, in leg order.
`dead_time_s` and `leg_phase_shift_s` default to 0.

Per leg, the cycle is the one the single-leg complementary mode already renders:

- high side on `[0, D·Tsw − td)`;
- low side on `[D·Tsw, Tsw − td)`;
- leg *k* is delayed by `k · leg_phase_shift_s`.

Within a pair the order of the two ids is a label, not a meaning. The compiler
still asks the one structural question it trusts: which switch's conducting path
reaches the reference net. That switch is the low side, and the other is the
high side. A pair whose two switches both reach the reference net, or neither
does, is refused rather than guessed.

Refusals reuse the existing compile vocabulary; **no compile code was added**:

- `pairs` missing or malformed, a switch named twice, a switch of the descriptor
  named in no pair (`details.components`), a pair naming a component that is not
  a switch: `invalid_control_declaration`;
- both switches of a pair reaching the reference net or neither:
  `ambiguous_complementary_control`, with `details.pair` and `details.low_side`;
- the two switches of a leg sharing one control net, two legs reusing one gate
  net, or a carrier on a net that is not a gate net:
  `ambiguous_complementary_control`;
- a gate net with no carrier: `no_carrier`;
- legs with different switching frequencies, `dead_time_s >= Tsw/2`,
  `leg_phase_shift_s >= Tsw`, or a carrier `dead_time_s` that disagrees with the
  declaration: `invalid_control_declaration`.

`CompiledCircuit.phases` now answers "how many switching phases did the one duty
drive": the number of phases for `single_duty_interleaved`, the number of legs
for `paired_complementary`, and 1 for a single gate or one complementary pair.
`compile-topology` and `simulate-topology` report the mode and the resolved
`gate_first_rise_s` as before.

`examples/topologies/two_leg_sync_buck.json` is two legs, 100 ns of dead time,
`leg_phase_shift_s = Tsw/2`, and one freewheeling diode per leg. The diode is an
explicit device because the reviewed synchronous template does not model a body
diode (`docs/65` §6); a leg without it truncates the inductor current in the
dead interval instead of freewheeling. The example is a user-owned circuit, not
a reviewed model.

Measured on ngspice (D = 0.5, Vin = 12 V, 100 kHz, 200 µs window, pre-charged
initial conditions):

```text
time-weighted duty per gate:             0.4905   ((D·Tsw − td)/Tsw = 0.49)
samples with both gates of one leg high: 0
second leg high-side rise − first:       5.000 µs
v(vout) mean:                            5.83 V   (D·Vin = 6.0 V)
max |v(sw1)|:                            12.0 V
```

The gap between 5.83 V and `D·Vin` is the freewheeling-diode forward drop, the
same effect `docs/64` records for the interleaved example. The 12.0 V line says
the switch node did not ring past the input rail; it is not a statement that the
circuit is accurate.

### 2. `switch_threshold_above_carrier_amplitude` (warning)

`validate-topology` now compares the two declarations that meet on a control net:
the switch's `threshold_v` plus `hysteresis_v` (defaults 0.5 V and 0) and the
driving carrier's `amplitude_v` (default 1.0 V). When the first is at least the
second, the switch can never conduct with that carrier, and the issue is
reported at the pointer of the key the document actually contains — the switch's
`parameters/threshold_v` when it is declared, its `parameters` object otherwise.

It is a warning, not an error, because a gate that stays off is a legitimate
command: a duty of zero turns every gate off, and the validator cannot tell an
intended open switch from an amplitude typed one digit too small. It is also not
a check of the solved waveform: `parameter_overrides` can change either number
at render time, while the validator only reads the descriptor.

### 3. Six defects found while building and auditing this

The mode itself was written first, and an independent read-only audit of it then
found defects in code that had passed its own tests. Each is fixed with a test
that fails without the fix:

1. **Two legs could share one gate net.** The cross-leg reuse check read a dict
   that is only populated at the end of the function, so it never fired; the
   second leg's window silently overwrote the first leg's, and one switch ended
   up with the other leg's shape and phase.
2. **A paired carrier could state a different dead time.** The single-leg mode
   refuses a carrier `dead_time_s` that disagrees with `metadata.control`; the
   paired mode did not, so a descriptor could say one thing and render another.
3. **The validator and the compiler disagreed about `phases: 2.0`.** The
   compiler accepts a whole number written as a float; the validator did not, so
   a document the compiler renders was reported as a declaration that does not
   fit, with a warning telling the author to fix something already right.
4. **A warning pointed at a key the document did not have.** `threshold_v` has a
   default, so it may be absent; the pointer now names an existing key.
5. **Two refusal messages described a world that no longer exists.** They said
   paired legs "have no declaration yet" and pointed at `docs/69`; they now point
   at the mode that expresses them.
6. **The `pairs` help text implied the order inside a pair mattered.** It does
   not, and the message now says so.

## Evidence

The full suite is **2088 passed / 2 skipped** with `PE_SIM_NGSPICE` set.

The paired declaration is pinned by compiled-gate tests (one declared dead time
per leg, the shift expanded as `k · shift`, cross-leg reuse refused, every
refusal path) and by a real-ngspice check of the shipped example: no sample has
both gates of a leg high, each gate's time-weighted duty is within 0.01 of
`(D·Tsw − td)/Tsw`, the two high sides are half a period apart within 5%, and
the mean output is within 8% of `D·Vin`. The warning is pinned by
`tests/test_topology_validation.py`: the code is in the closed set, is in
`WARNING_ISSUE_CODES`, is emitted at `warning` severity, and its pointer
resolves against a document that omits the parameter.

The two skipped tests are the ones that need a solver build the environment does
not have (see `docs/08`); they skip loudly rather than pass silently.

A topology an agent authors reaches at most `limited` evidence (`docs/64` §7).
Nothing in this release is a formal comparison, a hardware claim, or a statement
that a model is accurate.

## What this release does not change

`pe_sim.__all__`, `REQUEST_REJECTION_CODES` (still 6), `CIRCUIT_COMPILE_CODES`
(still 16), `plant_catalog()` keys, `time_model.py`, `reviewed_identities.json`,
and the visualization surface are unchanged.

`TOPOLOGY_ISSUE_CODES` changes from 26 to 27 (the new warning) and
`WARNING_ISSUE_CODES` from four to five. That is a contract event for a client
that branches on either set.

No body-diode model is added. No per-leg duty is added: every leg of a paired set
shares the one commanded scalar, and the legs differ only by the declared shift.
Arbitrary gate timing tables, multi-pulse-per-period modulation, and static gate
levels remain unexpressible and are listed in `docs/69`.
