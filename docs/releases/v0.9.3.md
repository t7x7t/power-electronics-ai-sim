# v0.9.3 — One Package-Integrity Rule

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## Why this release exists

The rule "the recorded derived hashes must agree with the manifest and with the
files on disk" was implemented once per reader: publication (`artifacts`),
`inspect_run`, `build_payload`, `load_run_evidence`,
`export_run_to_workbench_fixture`, and reproducibility comparison. Six copies of
one invariant is a maintenance hazard, and the copies had already drifted:

- `artifacts`, `reproducibility`, `postprocess`, and `workbench_export` checked
  the hash summary, both digests, and their format;
- `attestation` checked the digests and the summary but not the format;
- `inspection` checked the two digests and **not the summary at all**.

Consequence: a package whose `hashes` summary had been altered was accepted by
`inspect-run` and rejected by every other reader. That is the one place where a
user-facing "verify this package" command was weaker than the readers it was
supposed to summarise.

Reproduced before this release with `tests/test_package_integrity_consistency.py`:
`inspection accepted a package with an altered hash summary`.

## Changed

### 1. One implementation: `artifacts.verify_package`

`pe_sim.artifacts.verify_package(manifest, run_dir) -> tuple[str, ...]` now owns
the derived-hash protocol: hash format, summary consistency, and the two
recomputed digests. It returns every problem in a stable order and an empty tuple
when the package is self-consistent.

All six readers call it. Artifact-index equality, the `PUBLISHED` marker, and
provenance eligibility stay with the readers that need them, because not every
reader asks those questions.

Source delta: `+77 / −95` lines across six modules, and one rule instead of six.
`workbench_export._hash` is gone because the shared check subsumes it.

### 2. Two message changes

Messages now come from one place, so two assertions changed wording:

- `tests/test_attestation.py` matches `"hash summary"` instead of
  `"hashes summary"`;
- publication and post-processing report the canonical texts
  (`manifest_sha256 is missing or malformed`, `manifest hash summary is missing
  or inconsistent`, ...) instead of per-module variants.

Behaviour is unchanged except that `inspect-run` now reports the summary defect
it previously missed.

### 3. Frozen bypass surface (`docs/57`)

`docs/57_frozen_bypass_surface_v1.md` is the canonical, numbered list of what
this project will **not** defend against (N1-N8), together with the categories it
**will** keep fixing, the report format expected from an independent tester, and
the rule that a new adversarial check requires amending that document first.
`docs/38` §2.1 and `docs/03` §8 now point at it instead of keeping their own
copies of the list.

## Not changed

- No new module, no new public API name; `pe_sim.__all__` is untouched.
- `verify_package` is intentionally **not** exported: it is an internal reader
  contract, and the frozen public surface stays at 283 names.
- The identity-verification conditions from 0.9.2 are unchanged. Collapsing them
  into an `is`-comparison against a registration-held class was considered and
  deliberately deferred: it would change the verdict vocabulary, which is not a
  cleanup.

## Verification

- `tests/test_package_integrity_consistency.py`: 11 passed. Three cases (altered
  summary, altered contents, intact package) across four readers; the summary
  case failed on `inspection` before the change.
- Full suite: 1097 passed, 7 skipped.
