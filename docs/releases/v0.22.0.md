# v0.22.0 — Import a SPICE Netlist

**Status:** release note. This note describes what changed. It is not approval,
not a tag, and not a claim about any simulation result.

## What changed in this release

### 1. A front end from netlist text to a descriptor

`src/pe_sim/spice_import.py` is new. It reads the part of SPICE the closed
device vocabulary can express and returns the *same* descriptor document an
author would have written by hand:

- `V` as a DC `voltage_source` or, when the value is `PULSE(...)`, a
  `pulse_source`;
- `L`, `C`, `R` as `inductor`, `capacitor`, `resistor_load`, including the
  element-level `IC=`;
- `S` as `voltage_controlled_switch` and `D` as `freewheeling_diode`, with
  `.model SW(...)` / `.model D(...)` supplying the parameters the card does not
  state.

The result is an ordinary `topology-descriptor-v1`, so the whole existing loop
applies unchanged: `validate-topology`, `compile-topology`, `simulate-topology`,
and the registered `circuit-topology` plant. There is no second renderer and no
second execution path. The module is stdlib-only and never imports
`pe_sim.backends`; a test parses its own imports to keep that true.

### 2. Execution intent is dropped and listed; indirection is refused

`.tran`, `.options`, `.temp`, probe and analysis directives, and a whole
`.control … .endc` block describe *how* a netlist is run. The compiled topology
owns that, so the importer discards them and reports every discard in
`ignored_directives` with its line and a reason. Nothing is dropped silently,
and nothing in that list changes the circuit.

`.include`, `.lib`, `.subckt`/`.ends`, `.func`, `.global`, `.ic`, conditional
sections, and parameter *expressions* would make the imported circuit depend on
text the importer never read, so they are refusals. `.param NAME=<number>` is
accepted because substituting a literal number that is already in the file adds
no information the importer lacks. A refused `.subckt` is one defect, not one
per line inside it.

### 3. What it does not guess

- **Pulse width.** A carrier's PULSE card states a width, which is a duty
  ratio; in this project the duty ratio is a compile-time command. The importer
  records `observed_duty` and emits `pulse_width_not_imported` rather than
  putting a width into the descriptor.
- **Complementary gates.** Two carriers and two switches import, but the
  descriptor does not declare a relation between them. A
  `complementary_control_undeclared` warning names the declaration to add;
  inferring complementarity from two PULSE cards would be guessing a timing.
- **Scale factors.** `T`, `G`, `Meg`, `Mil`, `K`, `m`, `u`, `n`, `p`, `f` are
  understood; `a` (atto) is not, so `ic=0.45A` is an `invalid_value` instead of
  4.5e-19.
- **Node identity.** Node `0` becomes the reference net `gnd`; a real node named
  `gnd` becomes `gnd_2` rather than being merged with it. Every rename is
  reported in `net_name_map`.

### 4. Two answers instead of one boolean

`spice_import_document` reports `import_ok` ("did the netlist translate") and
`validation` (the topology validator's verdict on the descriptor that came out)
separately, with `ok` as the conjunction. An unmappable element and a dangling
node are different problems and should not look the same.

### 5. `pe-sim import-spice`

```text
pe-sim import-spice <netlist> [--topology-id ID] [--output PATH]
```

It prints the `pe-sim.spice-import.v1` envelope, writes the descriptor only when
one exists, dispatches before any plant registration, needs no solver, and adds
no rejection code. `REQUEST_REJECTION_CODES` is unchanged.

## Measured acceptance

- Round trip of the compiled Buck netlist (D = 0.5, Vin = 12 V, L = 100 µH,
  C = 470 µF, R = 10 Ω, fsw = 100 kHz, 10 ms): `compile → import → compile`
  reproduces every element and model card byte for byte; the only differing line
  is the order of the saved vectors in `wrdata`.
- Solved waveforms of the two netlists, 225,870 rows each: `v(vout)`, `i(L1)`,
  `v(sw)`, `v(vin)` and `v(pwm)` all differ by `0.000e+00`, point by point.
- `PE_SIM_NGSPICE` acceptance test: an imported hand-written netlist and the
  descriptor-compiled circuit agree on the final-window mean of `v(vout)` and
  `i(L1)` within 1e-3, and `v(vout)` is `D*Vin` within 0.15 V.

## Known limitations

- Six element letters and one waveform. No controlled sources, non-linear
  devices, transformers, mutual inductance, subcircuits, `.include`, parameter
  expressions, conditional sections, or node-level `.ic`.
- A `.control` block's *intent* (an `alter` sequence, a measurement) is not
  reconstructed; only its circuit skeleton survives.
- The vocabulary's own non-negativity bounds propagate: `voltage_v`,
  `initial_current_a` and `initial_voltage_v` are non-negative, so a negative
  supply or a negative initial condition imports and then reports
  `invalid_parameter_value` from the validator.
- Import is not review. An imported topology has no review record, so a formal
  comparison is capped at `limited`, an exploratory `QUALIFIED` run records
  `functional`, and `comparable` is unreachable.
- There is no reverse guarantee: a compiled window that starts inside a carrier
  pulse renders a `B` source for the tail, and that netlist cannot be imported
  back. It is a rendering detail of a window, not a circuit element.
