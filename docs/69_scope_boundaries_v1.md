# 能力边界声明（v1）

**状态**：范围声明。本文件列出**当前明确不支持**的东西，以及为什么、用户与 agent
应该如何表达、真要做时的最小改动。它不是路线图承诺，也不是缺陷清单——它是对
"你以为它能做，但它不做"的提前回答。

## 1. 为什么要把"不做"写下来

项目的分工是：内核提供器件词表、校验、编译、执行与测量的底座；具体拓扑、器件参数
与控制算法由用户和 agent 一起搭出来。在这个分工下，最大的失败模式不是"缺一个
拓扑"，而是**agent 以为底座能表达它想要的电路**，于是写出一份看起来合法、实际
不是那个电路的文档。

一次审计（2026-10-29）发现：显式写下的缺失比沉默的缺失便宜得多。沉默的缺失会让
agent 反复试错，或者更糟——用一个近似品蒙混过关，而近似品会产出**看起来正确**的
数字。

所以本文件对每一项给出三件事：

1. **不支持什么**（一句能判定的边界）；
2. **现在会发生什么**（拒绝码或校验结果，而不是"可能出错"）；
3. **替代表达**（用现有词表能做的最近一件事，以及它**不等于**原本想要的东西）。

## 2. 器件与物理层

### 2.1 磁耦合：变压器、耦合电感、多绕组

- **不支持**：任何需要互感、匝比、多绕组的元件。器件词表里没有 transformer，
  电感只有一个自感值。
- **现在会发生什么**：`describe-devices` 不列出该 kind；
  `validate-topology` 报 `unsupported_device_kind`（error）；
  `import-spice` 对 `.subckt` / 含多个电感耦合的网表报 `unsupported_directive`。
- **替代表达**：**没有诚实的替代**。用两个独立电感"假装"耦合电感会漏掉励磁电流
  的去向，得到的波形比没有更误导。
- **最小改动**：在 `circuit_devices` 增加一个 `transformer` 种类（端口：两个绕组的
  四端），在 `circuit_compile` 渲染为 ngspice 的耦合电感（`K` 元件 + 两个 `L`），
  并给 `topology_validation` 增加"耦合系数必须成对声明"的检查。这一项会影响
  隔离型拓扑的全部：反激、正激、LLC、全桥隔离。

### 2.2 开关器件物理

- **不支持**：反向恢复电荷、结电容、栅极电荷、跨导、沟道长度调制、温漂。
- **现在会发生什么**：开关被渲染为 ngspice 的电阻型 `SW` 模型（`Ron`/`Roff`/
  `Vt`/`Vh`），二极管被渲染为指数型 `D` 模型（`Is`/`N`）。声明 `circuit_devices`
  未列出的参数会被 `validate-topology` 报 `unknown_parameter`。
- **替代表达**：`on_resistance_ohm` 覆盖通态损耗；反向恢复与结电容**无法**近似
  成电阻，所以 100 kHz 以上的开关损耗与振铃不会被这个模型测出来。
- **最小改动**：在 `circuit_devices` 的开关种类上增加 `reverse_recovery_charge_c`
  等参数，并在 `circuit_compile` 里改用 `SW` + 并联 `C` + 体二极管子电路。
  注意这会把渲染从"一条元件卡"变成"一个子电路"，需要重新定义
  `CIRCUIT_NETLIST_TEMPLATE_VERSION`。

### 2.3 非线性磁性元件

- **不支持**：饱和、磁滞、随电流变化的电感。
- **现在会发生什么**：`inductance_h` 是常数；`initial_current_a` 只设初值。
- **替代表达**：**没有**。饱和是开关电源过流的物理来源，用常数电感测不出来；
  "电流超过某个值就报错"是保护逻辑，不是饱和。
- **最小改动**：渲染为 `L` 的 B-H 表模型（ngspice 的 `Chan` 模型），需要新增
  一组磁芯参数并在 `circuit_devices` 里声明。

### 2.4 热

- **不支持**：器件温升、热网络、温度对 `Ron` 的影响。
- **现在会发生什么**：网表带 `.temp <T>`（默认 27 °C），温度是编译参数
  `temperature_c`，不是待求量；器件参数不随温度变化。
- **替代表达**：把想考察的温度点作为 `temperature_c` 传进去，做多次编译——这
  回答"在 100 °C 下损耗是多少"，不回答"损耗会让它变成多少度"。
- **最小改动**：增加热网络元件种类与"损耗 → 温度"的迭代外层；这会引入第二组
  状态变量，属于新的执行语义，不属于现有词表。

## 3. 源与网

### 3.1 正弦、任意波形、AC 大信号

- **不支持**：正弦源、PWL 任意源、噪声源、调幅/调频源。
- **现在会发生什么**：`voltage_source` 只有一个 `voltage_v`（直流值）。
  `import-spice` 对 `SIN(...)`/`PWL(...)`/`EXP(...)` 报
  `unsupported_source_function`（`PULSE` 是唯一的例外，因为它就是一个栅极载波）。
- **替代表达**：**没有**。用一串直流源拼接正弦是一个需要求解器配合的分段仿真，
  它不会给出连续的波形。
- **最小改动**：给 `voltage_source` 增加一个"波形"声明（`kind` + 参数），并在
  `circuit_compile` 里渲染成 ngspice 的 `SIN`/`PWL`。这会打破"一个源一个标量"
  的简洁性，所以要么新增源种类，要么引入一个显式的波形子对象。

### 3.2 三相与多相交流系统

- **不支持**：三相电压源、三相负载、线电压/相电压、dq 变换。
- **现在会发生什么**：没有三相机型；三台独立直流源不能组合出三相系统。
- **替代表达**：**没有**。三相系统的关键是三个相之间的**同时**关系，而内核的
  指令是一个标量。
- **最小改动**：见 §4.1——先要有"多个独立指令"的请求形状。

## 4. 控制与指令

### 4.1 多桥臂独立控制

- **不支持**：一相一个占空比、三个桥臂三个指令、任意的栅极时序表。
- **现在会发生什么**：`ActionRequest` 携带**一个**无量纲的 `normalized` 标量。
  描述符可以在 `metadata.control` 里声明"这一个指令如何派生成多个栅极"，可选
  关系是 `single_duty_complementary`（一对互补，含死区）、
  `single_duty_interleaved`（N 个等间隔相位，同一占空比）与
  `paired_complementary`（N 条腿各自互补、腿间按声明错相，同一占空比）。其它
  关系一律拒绝：未声明时多开关报 `multiple_actuators`，声明与图形不符时报
  `invalid_control_declaration`。
- **替代表达**：
  - 多相 DC-DC（每相一个栅极）→ `single_duty_interleaved`，**相位**不同、
    **占空比**相同；
  - 同步 Buck → `single_duty_complementary`；
  - 多条各自互补的腿、腿间错相（两相同步 Buck）→ `paired_complementary`
    （`leg_phase_shift_s = Tsw/2`）。全桥单 duty 双极性调制是同一声明形状，但
    本仓库没有该样例；
  - 三相逆变器 / 每条腿要**各自不同**的占空比 → **没有**，因为一个标量指令
    无法给出三个不同的 duty（或一个带符号的调制波）。
- **最小改动**：把 `ActionRequest` 的单一标量换成"标量数组 + 一份指令与栅极的
  映射声明"。这是一次**内核契约变更**，会波及 `contracts.py`、`runtime.py`、
  每个 plant 与控制器，以及所有已评审身份，因此它必须是一次独立、被评审的
  版本化改动，而不是顺手加一个字段。

### 4.2 内置调制器与闭环控制器
- **不支持**：项目**不内置**电流模式、峰值电流、平均电流、电压前馈、PFC 双环等
  控制器作为内核组件。
- **现在会发生什么**：`controller_registry` 里有 `pid` 等已注册控制器；
  `validate` 的 controller 阶段比对 `controller_id` 与已注册的声明，未知则报
  `unknown_controller`。拓扑执行路径（`simulate-topology`）是**开环**的：一个
  窗口内占空比恒定。
- **替代表达**：`PlantObservation.measurement` 是一个开放映射，
  `circuit_plant` 已经把 `inductor_current` 发布出来，所以用户可以在自己的
  `plant_config` 侧写一个控制器来用。缺的只是公开地位与样例，不是能力。
- **最小改动**：在 `examples/` 增加一份"用 `inductor_current` 做峰值电流限制"
  的样例，并把 `controller_registry` 的声明扩展为可带值类型。这不改变内核。

### 4.3 每周期多次通断的调制

- **不支持**：跳周期（pulse skipping）、突发模式、迟滞控制、恒定导通时间（COT）、
  二极管仿真（防倒灌）等"在一个载波周期里多次通断"的调制。
- **现在会发生什么**：`_render_gate` 对每个控制网只渲染**一张** `PULSE` 卡，宽度
  来自唯一一个开通窗口，所以每个栅极每周期恰好通断一次。**这类需求不会被拒绝**：
  `compile-topology` 照常成功，把命令占空比渲染成连续 PWM。你想要的 DCM 行为不会
  出现，拿到的是另一个电路的 CCM 波形。
- **替代表达**：把命令占空比设到目标平均值的等效值，然后接受"这是平均 PWM，不是
  跳周期"。这不等价。
- **最小改动**：一个栅极需要多个窗口，意味着 `gate_windows` 从"一个网一个区间"变成
  "一个网一串区间"，`_render_gate` 变成多段 PWL，并需要一个明确的拒绝码说明
  "本基座每周期每栅极一个脉冲"。

### 4.4 静态栅极电平（一条腿常通 / 常断）

- **不支持**：声明某个栅极恒高或恒低（四开关 buck-boost 的 buck/boost 区切换需要
  它）。
- **现在会发生什么**：占空比 0 会让**所有**栅极恒低（渲染为 `DC 0`）；占空比 1
  会让**所有**栅极恒高。没有"这一个栅极恒高、其余照常"的写法，因为唯一能驱动
  `control` 网的元件是 `pulse_source`，而它的脉宽来自全局那一个 duty。
- **替代表达**：**没有**。把某个相位写成常通只能靠 `duty = 1`，那会同时改掉所有
  其他栅极。
- **最小改动**：新增一种能驱动 `control` 网的直流电平元件，或在
  `metadata.control` 里声明"该网关断"。

### 4.5 多桥臂：每条腿各自的占空比

- **不支持**：一条腿一个占空比、三桥臂三个指令、任意的栅极时序表。
- **现在会发生什么**：`ActionRequest` 仍只携带**一个**无量纲的 `normalized`
  标量。多条腿各自互补、腿间错相**已经可以表达**（`docs/64` §5.8）：

  ```json
  {"mode": "paired_complementary", "pairs": [["s1","s2"], ["s3","s4"]],
   "dead_time_s": 1e-07, "leg_phase_shift_s": 5e-06}
  ```

  仍不支持的是给每条腿**不同**的占空比。把四开关电路写成
  `single_duty_complementary` 会以 `ambiguous_complementary_control` 拒绝
  （`details.actuators` 是 4）；写成
  `{"mode": "single_duty_interleaved", "phases": 4}` 则**校验通过、编译成功**，
  四个栅极得到等间隔的同一个占空比，同一腿的高边与低边在高占空比下同时导通。
  编译器只渲染你声明的关系，它不知道哪两个开关属于同一条腿——除非你用 `pairs`
  说出来。
- **替代表达**：所有腿共享一个 duty、腿间只差相位 → `paired_complementary`。它
  **不等于**每腿独立调节：三相逆变器的三个调制波仍无法表达。
- **最小改动**：把 `ActionRequest` 的单一标量换成"标量数组 + 一份指令与栅极的
  映射声明"，见 §4.1。这是内核契约变更。

### 4.6 开关阈值与载波幅度的交叉检查

- **已做（警告，不是错误）**：`validate-topology` 现在比较开关声明的
  `threshold_v + hysteresis_v`（默认 0.5 V 与 0）与驱动其控制网的
  `pulse_source.amplitude_v`（默认 1.0 V）。前者不低于后者时报告
  `switch_threshold_above_carrier_amplitude`（`severity = "warning"`），`ok`
  仍为 `true`，编译器照常渲染。
- **仍不做**：不检查求解出的栅极波形。`parameter_overrides` 可以在渲染时改掉
  `amplitude_v` 或 `threshold_v`，而校验器只读描述符。所以这条警告只代表
  "按这份文档声明的两个数字，这个开关不会导通"。
- **为什么是警告**：一个栅极保持关断是合法命令（占空比为 0 时所有栅极都关断），
  校验器无法区分"我故意让它关断"与"我把幅度写小了"。
- **现在会发生什么**：把 `amplitude_v` 写成 0.3 或 `threshold_v` 写成 1.5，文档
  得到一条警告；若忽略它，编译与执行都会成功，波形是一条看起来"合理"的平线。
  执行 `simulate-topology` 后看 `metrics.carriers[].observed_duty`：它接近 0 而
  命令占空比不是 0，就是这个错误。
- **替代表达**：不需要替代——把 `threshold_v` 降到 `amplitude_v` 以下，或把
  `amplitude_v` 提高。

## 5. 分析与求解
### 5.1 周期稳态（PSS）与频响扫频

- **不支持**：PSS 求解、AC 扫频、Bode 图、环路增益。
- **现在会发生什么**：`pe-sim capability` 的 AC/阻抗分析是**单点线性化**
  （在某一直流工作点求一次雅可比），`ac-analysis` 与 `impedance-analysis` 信封
  都只描述一个频点。没有扫频。
- **替代表达**：在若干直流工作点上各做一次单点线性化并自己拼出曲线；这不是
  扫频，但**在每个点上**都是真实的线性化。
- **最小改动**：在 `pe_sim.ac_analysis` 上增加频率参数与一个多点外壳。

### 5.2 收敛性与数值健康

- **不支持**：保证收敛。求解器可能不收敛或超时。
- **现在会发生什么**：`simulate-topology` 把这类失败报告为
  `status: "FAILED"`、`category` 为 `backend_timeout` / `numerical_nonconvergence`
  等，**退出码 1**。它不是请求错误：去改文档会改错文件。
- **替代表达**：减小步长（`--step`）、换积分器（`--integrator`）、给出更接近
  工作点的初值。

## 6. 编排

### 6.1 学习与优化

- **不支持**：任何形式的在线学习、参数寻优、强化学习闭环。
- **现在会发生什么**：没有对应接口；`docs/20` 说明可选学习边界始终在
  "建议"一侧，不参与证据。
- **替代表达**：用 `study` 做参数扫描，用 `compare-runs` 比较结果，把选择留给人。

### 6.2 可视化 UI

- **不支持**：项目**不提供**浏览器界面或桌面 UI。
- **现在会发生什么**：存在三个渲染器中立契约（`TopologyDescriptor`、
  `TraceDataset`、`OutputDataset`）、`export-workbench`（离线数据导出）与
  `visualization-serve`（回环只读 JSON 服务）。未来的 UI 必须只消费这些契约，
  不得获得 Runner、Plant、Controller 或变更权限。
- **替代表达**：这些契约就是替代表达——UI 是消费方，不是本项目的交付物。
