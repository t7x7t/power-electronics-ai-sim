# v0 AI Agent 操作与约束策略

**适用对象**：在本项目中读取代码、修改实现、执行仿真或整理证据的 AI Agent。

本文件约束 Agent 的操作方式，不授权 Agent 做工程安全判断。人类工程师仍负责
额定值、器件边界、模型适用性、发布许可和最终结论。

## 1. 工作区权限

默认允许：

- 读取项目源码、配置、测试、文档和公开样例；
- 写入当前任务声明的源码、测试、文档和独立 `runs/` 目录；
- 执行静态检查、单元测试、契约测试和明确批准的 smoke 仿真。

默认禁止：

- 修改或删除锁定基线、历史证据和他人未提交修改；
- 访问密钥、凭据、私人数据或未发布硬件资料；
- 直接写入真实硬件、编程器、串口或台架控制接口；
- 将 `Plant` 内部真值注入 Controller；
- 使用未来样本生成当前动作；
- 通过删除失败日志、放宽阈值或覆盖 Manifest 使运行变为成功。

### 1.1 机器可检查的控制

以下控制由代码执行，不依赖 Agent 自觉遵守：

- `--mode formal_comparison` 在创建运行目录前拒绝 dirty/unknown 工作树，并拒绝
  `implementation.review.status == "unreviewed"` 的参考适配器；
- `reviewed_identities.json` 固定已评审的求解路径指纹。任何电路构建、进程执行、
  求解设置或波形解析代码变更都会改变指纹，并由测试强制要求更新评审记录；
- `pe-sim inspect-run` 重新校验 Manifest/包摘要、产物索引、发布标记、采样单调性
  与非有限值，并报告 `implementation.review.status`；
- `pe-sim describe <plant_id>` 在写文档前打印该 plant 的 `plant_config` 声明
  （类型、单位、边界、默认值），不构建 plant、不调用工厂；
- `pe-sim validate <config>` 在构建 plant、启动求解器、创建运行目录之前，用同一份
  声明与实验 Schema 检查文档，并按 JSON Pointer 输出结构化问题（`docs/63`）；
- `pe-sim describe-devices [kind]` 打印拓扑可用的封闭器件词表（端口、网种类、参数、
  单位、是否可渲染），不加载注册根、不导入后端；
- `pe-sim validate-topology <file>` 在编译之前检查拓扑文档的结构与语义（连通性、
  参考网、控制网、电压源回路），并报告 `checked` 实际跑过的检查组（`docs/64`）；
- `pe-sim import-spice <netlist>` 把已有的 SPICE 网表子集翻译成同一种拓扑文档；
  词表外元件与不可推导的指令逐条报告，不静默丢弃（`docs/66`）；
- `pe-sim compile-topology <file>` 把拓扑文档渲染成确定性网表，不执行任何求解；
  渲染不了时给出封闭的拒绝码，不做近似；
- `pe-sim preview-netlist` 在不启动仿真器的情况下渲染网表，供人工核对电路；
- 后端失败时保留有界日志摘要（`failure.backend_evidence`）。

这些措施让改动“可见、可复核”，不是不可绕过的安全边界。Runner、产物写入和资格
判定代码目前只由 Git 提交与工作树状态保护；签名发布和 SBOM 属于后续工作
（`docs/37` UD-06）。提示词规则不能替代上述检查。

## 2. 命令策略

命令分为三类：

| 类别 | 示例 | 规则 |
|---|---|---|
| 只读 | `git status`、文件搜索、版本查询 | 可直接执行 |
| 可逆验证 | 单元测试、契约测试、最小 smoke | 记录命令和输出 |
| 有副作用 | 大规模仿真、基线更新、合同修改、发布 | 必须先说明影响并获得人工确认 |

禁止使用不可逆清理、强制覆盖、重置分支或批量删除结果的命令。需要清理时只能
操作任务创建的临时目录，并先核对绝对路径。

## 3. 每次任务的强制流程

1. 声明目标、范围、输入和预期产物。
2. 读取相关 L0/L1 文档、调用者和现有测试。
3. 检查 Git 状态、环境和基线 Hash。
4. 先编写失败测试或失败模式，再修改最小范围代码。
5. 若任务新建或修改实验文档（`pe-sim run` 的输入），在创建任何运行目录之前运行
   `pe-sim validate <config>`，并按 `issues[].path` 修到 `ok: true`。该命令不构建
   plant、不实例化或调用适配器、不启动求解器、不创建运行目录，是零副作用自检回路；
   它同时比对控制器注册声明（`controller_id` 与 `controller_config` 的键名）。
   通过只表示文档与当前声明一致，不表示电路正确或可发布（`docs/63`）。
6. 若任务编写或修改电路拓扑文档，先按 `pe-sim describe-devices` 的声明写；从已有
   网表起步时用 `pe-sim import-spice` 生成初稿（它只产出同一种描述符，不是第二条
   执行路径）。再运行 `pe-sim validate-topology` 修到 `ok: true`，最后用
   `pe-sim compile-topology` 确认能渲染。**可编译不等于模型被评审**：Agent 自行
   编写或导入的拓扑没有评审记录，其产出最高为 `limited` 证据，不得暗示
   `comparable`（`docs/64`、`docs/66`）。
7. 运行针对性测试，再运行相关集成测试。
8. 对 Manifest、状态、资格、安全和因果边界做审计。
9. 保留失败产物，生成变更摘要、命令、限制和未完成项。

任务未完成时必须明确标记 `INCOMPLETE`，不能用“代码已修改”代替验证结论。

## 4. 必须停止并请求人工确认的情况

- 修改 Plant 参数、初态、安全合同或基线 profile；
- 改变 Controller 可见字段、时间因果或执行边界；
- 出现安全阈值冲突、合同 Hash 不匹配或未知模型来源；
- 测试无法收集、环境版本不一致或 Ngspice 反复失败；
- 结果可能被解释为器件、硬件、实时性或产品安全结论；
- 需要迁移、删除或公开第三方资料。

## 5. Agent 输出格式

每次任务结束必须报告：

```text
目标与范围
修改文件
执行命令与环境
测试/仿真结果
Manifest 或产物路径
状态与证据等级
失败、限制和未完成项
是否需要人工批准
```

## 6. 可选学习/适配隔离

学习和自适应不是核心基础设施的必选能力。项目不提供内置训练器、在线学习循环、
自动参数优化或自动替换 Controller/Plant；需要这些能力的用户应通过独立、可审查的
适配器接入。

只有在学习扩展明确启用、运行达到 `LEARNING_ELIGIBLE`，并且来源、配置、合同、
资格和人工审查条件均满足时，事件或数据才可以交给外部学习器。探索性结果、资格
失败结果、合同不匹配结果、dirty/unknown 来源和人工未审查结果只能用于诊断；Agent
不得自动把它们加入公共库、更新控制器或覆盖基线。任何学习更新都必须保留输入与
输出 Hash、适配器版本、准入依据和可逆的审计记录。
## 7. 后续计划：用户授权与变更可见性（Phase E，尚未实现）

Phase E 将增加机器可读的 `change_control` 报告与用户授权记录，使用户能够看到
Agent 何时修改了 Plant、Runner 或 Controller、修改了哪些文件，并确保未授权修改
不能产生正式证据。当前规则在该阶段 E1/E2 落地前保持不变；外层工具写权限锁定属于
产品阶段。设计见 `docs/52_user_change_authorization_v1.md`，阶段定义见
`docs/43_kernel_roadmap_v1.md` 的 Phase E。

## 8. 审计意见分诊：可信度问题与对抗性问题

外部审计经常以对抗方式描述问题（“用如下代码即可绕过”）。分诊依据不是能否构造
出绕过，而是**该路径在非恶意使用中是否可能出现**：

| 报告类型 | 例子 | 处理 |
| --- | --- | --- |
| 误归属 | 把参考实现拷到自己的目录后改动，仍声明被审的 `backend_id` | **必修**：这是 agent 非恶意修改的真实形态 |
| 漏声明 | 未声明自己的 backend，却在清单里出现被审模块名 | **必修** |
| 记录漂移 | 改了代码或 pin 未同步，导致复核状态过期 | **必修**（由测试强制） |
| 虚假通过 | 报告类型声明与实测不符、证据等级高于实际 | **必修** |
| 进程内对抗 | 改写 `sys.modules`、改写 `pe_sim.identity` 本身、替换实例属性、伪造 `co_filename` | **不修**：见 `docs/57_frozen_bypass_surface_v1.md` §3 的 N1–N8，属已声明边界 |
| 沙箱/签名/密钥 | 要求运行时证明“这是谁的进程” | **不修**：属 Phase E/产品阶段，不是内核职责 |

对应的判断标准只有一条：**内核重新计算，适配器只能声明**（I2）。凡是要求内核
去证明它无法拥有的事实（任意对象的代码出处、进程身份、签名密钥），一律归为
非目标并补写文档，而不是再加一道检查。每增加一道对抗性检查，都必须同时说明它
防守的是哪一类非恶意失败；说不出来的，不加。

已冻结的具体条目（N1–N8）与面向测试方的提报格式，统一维护在
`docs/57_frozen_bypass_surface_v1.md`；本节的表格只定义分诊原则，不重复条目清单。
